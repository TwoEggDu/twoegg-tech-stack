# 项目与团队管理系列规划

> 更新：2026-11-03。角色：本系列唯一 canonical 篇级目录与状态源。正文推进见[专栏执行计划](project-management-execution-plan.md)，首页执行层见[首页组织提纲](project-management-homepage-outline.md)，公开阅读入口见[详细阅读提纲](../content/project-management/project-management-series-index.md)。

## 1. 定位与已确认选择

用户确认新增“项目管理”页签，紧邻“工程与交付”，进入后的标题为“项目与团队管理”。先建立完整、可独立学习的通用管理知识，再进入软件研发应用，最后连接游戏研发场景。人员管理、会议组织与方法工具是明确需求，不能只以排期和催进度覆盖。

本系列服务于开始负责项目的成员、团队负责人和希望改善协作的研发人员。通用部分不要求 Unity、软件开发或游戏生产背景，也不以作者先提供个人案例为起草前提。

首版产物是首页和 32 个主题的详细提纲，现从 PM-01 开始逐篇补齐正文。主题数量是当前目录规模，不表示已有课程篇数；不生成空文章占位。详细提纲给出核心问题、展开要点及拟安排的练习，正文通过审核与检查后接入真实文章链接。

## 4. 阅读与写作顺序

系统阅读：01—03 建立语言，04—10 形成项目主线，11—14 讨论人员支持，15—19 组织沟通决策，20—23 进入改进。24—32 分别进入研发与游戏应用，各篇只列实际依赖，不把整套课程设为硬前置。

首批优先起草：

1. 01 → 04 → 05 → 06：从结果到范围、工作分解、依赖与进度，形成可用的项目管理起点。
2. 11 → 12：回应如何支持不同任务中的成员，说明授权和检查的关系。
3. 18 → 21：回应会议组织和鱼骨图等工具需求；补必要的沟通、决定与证据概念，并链接后续专题。
4. 再按实际需要补风险、变更、验收、反馈、复盘；应用篇在必要基础可用后推进，不等全套成稿。

拟采用的通用教学情境是“组织一次小型培训活动”，可贯穿目标、场地与材料依赖、人员分工、预算、风险、会议和验收。它是教学设定，任何工期与成本数字都标为模拟；人员讨论采用虚构人物，不借此编造作者经历。研发探索和游戏生产另外使用适配的例子，避免把活动项目模型强套到所有工作。

2026-11-03 已将以上顺序细化为[专栏执行计划](project-management-execution-plan.md)：先完成 PM-01，再形成首批 8 篇可读内容，随后补齐 23 篇通用基础并扩展研发与游戏应用。用户已授权逐篇写作、独立 subagent 审核、修改复审，通过检查后提交推送，再进入下一篇；执行计划记录具体顺序、阅读对应与接续方式，不改动本表的篇目职责。

## 5. 方法与工具的归属

工具是知识的用途索引，不另建一套竞争的篇级目录。首版在公开阅读提纲中提供四组锚点：

| 用途 | 工具 | 所属主题 |
| --- | --- | --- |
| 拆解与排期 | WBS、依赖网络、关键路径、甘特图、资源成本表 | PM-05/06/07 |
| 分工与沟通 | RACI、干系人分析、沟通计划、会议议程、决定记录 | PM-02/15/16/18/19 |
| 风险与诊断 | 风险登记表、概率影响矩阵、时间线、鱼骨图、5 Whys、帕累托图 | PM-08/20/21 |
| 跟踪与软件 | 看板、在制品限制、周期时间、行动表、管理软件 | PM-20/22/23/25/27 |

每种工具的正文覆盖：要解决的问题、输入信息、使用步骤、输出怎样支持决定、适用条件、误用和维护成本。Jira、飞书、Excel、Microsoft Project 按共同工作模型比较，实际软件演示另记版本、环境与操作验证，不能由模板草图推定软件已经支持或配置完成。

| PMI，PMBOK 指南 | 体系覆盖与术语核对 | 第六版文件仅确认存在；上传的第八版 PDF 未确认与官方中文出版版一致。引用前核对版本、原文及出版信息，不写已通读 |

出版信息与书中具体主张需在单篇写作时固定引用版本；本文不把三本书改排成章节摘要，也不把所有工具一概归到某一版 PMBOK。书籍文件继续保留在外部阅读资料中，不进入公开仓库。

编辑边界：

- 任务相关成熟度用来决定具体任务的支持方式；干系人分析用来安排参与和沟通，二者不混用为人员分类或待遇等级。
- 人员培养、反馈和表现讨论可以展开；招聘、薪酬、晋升和劳动关系制度暂不扩成课程，必要时说明组织政策边界。
- 鱼骨图提供候选原因，连续追问提供调查方向，因果判断依赖证据；不要求机械追问五次，不预设固定的二八比例。
- 会议时长、检查频率与分工方式依据任务和组织条件选择，不把某本书的做法写成普遍强制规定。
- 游戏案例区分本人职责、他人贡献、实际动作、采用情况与结果；没有同口径数据时不生成改善百分比。
