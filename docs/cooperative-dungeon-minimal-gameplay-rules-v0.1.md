# 无尽对决最小玩法规则 v0.1：标记、引爆与一次性结算

日期：2026-10-25（Asia/Shanghai）

> v0.1 规则已确认，游戏待实现与验证。数值是教学基线，尚未经过试玩或平衡验证。项目采用 Unity 实际落地；Unreal、Piccolo 仅作方案讨论。设计与独立教学材料公开，Demo 工程保持私有。

## 1. 目标、范围与选择理由

用一张斜俯视小场地、两名角色、一种普通怪和一种测试奖励，完成“进入 → 清怪 → 简单结算 → 返回 → 重开”。两名角色各有移动、普攻和一个主动技能。A 施加标记，B 消耗有效标记获得额外伤害，让玩家观察释放顺序与队友配合的收益。

首版采用自动选敌。手动点选更精确，但会增加选中、切换与触屏交互；自动选敌让玩家通过走位接近目标、通过按键顺序配合，也便于在固定场景中复现实验。技能衔接带来收益，普通攻击仍可参与清怪，方便单项调试。

不增加复杂 Boss、机关、职业、装备、成长、闪避、复活、手动瞄准、弹道或遮挡判定。首版使用开阔场地。本文固定玩法规则，不规定网络同步算法、引擎类结构或设计模式；Unity 承担实施与验收。

## 2. 目标选择与释放

| 项目 | v0.1 规则 |
| --- | --- |
| 有效目标 | 与施放者处于同一局、存活、距离不超过 6 米的怪物；等于 6 米时仍有效 |
| 普攻与 A 技能 | 在有效目标中选择距离最近者 |
| B 技能 | 优先在有效目标中选择有有效标记的怪物；多个标记目标取最近者；没有标记目标时选最近普通目标 |
| 距离相同 | 按稳定的怪物实例 ID 升序选择；实例 ID 不等于怪物配置 ID |
| 无有效目标 | 提示“范围内无目标”，不产生效果、不开始冷却 |
| 冷却未结束 | 不产生效果，不重置或延长当前冷却；界面显示剩余冷却 |
| 已倒下／已结束 | 角色倒下、本局结束或测试中止后，不再接受战斗操作 |
| 生效时刻 | 服务端接收、校验并处理成功后立即生效；动画、特效表达结果，不决定命中时刻 |

目标筛选以服务端处理该操作时的权威状态为准，不依赖客户端按钮按下时看到的旧位置或旧标记。B 的“标记优先”只作用于 6 米内有效目标，不会因为范围外存在标记就拒绝攻击范围内普通怪。目标在校验时已倒下或不属于本局，也不能受到本次攻击。

距离的坐标约定、Unity 单位与米的换算在实现设计中固定，两端采用一致口径；这不改变上述 6 米边界。首版不增加手动锁定，玩家用走位影响候选目标。

## 3. A 的主动技能：标记

| 项目 | v0.1 规则 |
| --- | --- |
| 作用对象 | 按第 2 节选择一个有效目标 |
| 伤害 | 不造成伤害 |
| 持续 | 成功施加后持续 5 秒 |
| 冷却 | 成功施加后冷却 6 秒；无目标或操作被拒绝时不开始冷却 |
| 层数 | 同一目标最多一层，不叠加层数 |
| 重复施加 | 重新成功施加时，剩余时间重置为 5 秒，不在原剩余时间上累加 |
| 表现 | 目标头顶显示可辨认的标记及剩余时间 |
| 清理 | 被 B 消耗、自然到期、目标倒下、本局结束或测试中止时清理状态与表现 |
| A 倒下 | 已施加的标记仍持续到正常结束；A 自己不能继续施放 |

5 秒持续与 6 秒冷却意味着，默认配置不能靠连续施放 A 无限维持同一标记。重复施加仍有明确规则，供配置变化或指定测试场景验证，不因此增加刷新按钮。

## 4. B 的主动技能：引爆

| 项目 | v0.1 规则 |
| --- | --- |
| 作用对象 | 按第 2 节优先选择有效标记目标，否则选择普通目标 |
| 基础伤害 | 对选中的目标造成 20 点伤害 |
| 标记收益 | 目标有有效标记时，消费该标记一次，额外造成 30 点伤害，合计 50 点 |
| 没有有效标记 | 仅造成 20 点基础伤害，不产生额外效果 |
| 冷却 | 成功攻击后冷却 4 秒；有无标记均进入冷却 |
| 一次性 | 同一个标记只能被成功消费一次；同一次技能操作不能因重复请求重复扣血 |
| 表现 | 普通命中与成功引爆有可区分反馈，显示本次伤害结果 |

B 提前释放仍有基础作用，但会占用冷却；等待 A 标记后再释放，可以观察 20 与 50 的差别。伤害超过目标剩余生命时，50 仍是本次规则计算的伤害值，不要求目标实际损失的生命超过其剩余生命。

消费与对应伤害属于同一次规则操作。不能出现标记被消费却漏掉对应伤害，或一次消费产生两次额外伤害；具体实现方式留给 Unity 设计。

## 5. 时间边界、操作顺序与重复请求

时间使用服务端的权威规则时间。标记有效条件为“当前时间小于截止时间”，冷却完成条件为“当前时间大于或等于可再次施放时间”。客户端倒计时只用于反馈，不独立决定结果。

例如，A 在规则时间 10 秒成功施加：标记在 15 秒失效，A 在 16 秒可再次施放。B 在 14.9 秒处理成功可引爆，在 15 秒处理则没有额外伤害；如果此时仍有普通有效目标，B 按无标记的技能效果结算 20 点伤害，并开始 4 秒冷却。这些是预期样例，不是实测数据。

同一步中的技能按服务端处理顺序执行：

1. A 先成功施加，B 后处理时可以消费。
2. B 先处理时只按当时状态结算；A 随后施加不会追补 B 的伤害。
3. 重复请求返回或引用原操作结果，不再施加、扣血、消费或重新开始冷却。
4. 旧局请求不能操作新局；已结束实例不能重新进入运行状态。

动画替换、特效延长和客户端显示延迟，不改变规则时间或处理顺序。实施时需要能观察本局、角色、目标、操作身份、处理顺序、时间与结果；具体协议字段与更新频率尚未选定。

## 6. 开局、胜负与测试中止

| 环节 | v0.1 规则 |
| --- | --- |
| 开局 | 完成配置检查，一次生成本局配置中的全部怪物，不设波次；怪物清单为空属于配置错误，禁止开始 |
| 胜利 | 本局怪物全部倒下，且至少一名玩家存活 |
| 失败 | 两名玩家全部倒下；仅一人倒下时继续，由存活队友完成 |
| 同一步清怪且全员倒下 | 本次权威规则更新结束后，统一读取最终状态；先判断全员倒下，失败优先，再判断清怪胜利 |
| 结束 | 固定本局结果一次，停止接受后续战斗操作并清理临时状态；迟到消息不能改变结局 |
| 断线 | 运行中任一客户端断线，本局标记为“测试中止”，双方退出战斗，不发奖励；不提供中途恢复 |
| 返回重开 | 清理本局状态，新局使用新实例 ID，重新初始化角色、怪物、技能冷却和标记 |

测试中止用于区别于玩法失败。结束已经确定后发生的断线，不再将胜利改为中止或重新发放奖励。只有正常初始化的本局怪物全部倒下才满足清怪条件；空配置不能靠“剩余数为零”直接获胜。

单项内容预览可以只启动一个客户端，但不能替代两独立客户端的合作与结算验收。

## 7. 测试奖励与保存范围

| 项目 | v0.1 规则 |
| --- | --- |
| 奖励类型 | 一种“测试徽记”，不引入背包经济或消耗用途 |
| 胜利 | 本局两名参与者各获得 1 枚；倒下的参与者也获得 |
| 失败／测试中止 | 两人均为 0 枚 |
| 发放次数 | 同一副本实例只结算一次，分别记录两名参与者的结果；重复请求或重复打开结果界面不增加数量 |
| 新局 | 新实例正常完成后可以再次获得奖励 |
| 返回重开 | 保留各测试身份的累计徽记数量，重置战斗状态 |
| 保存方式 | 只保存在本地测试服务的内存中；重启测试服务后累计数量与记录清零，不承诺重启恢复 |

测试身份须在同一次测试服务运行期间稳定，才能观察返回重开后的累计数。玩家身份与副本实例身份分别记录；实际测试入口与身份分配方式在 Unity 实现设计中确定，不要求真实账号系统。

测试中止后的新局初始化不撤回此前已完成局的奖励。一次性结算的教学结论只覆盖当前服务进程的内存记录，不代表数据库事务或生产级奖励可靠性。

## 8. 配置、工种交接与教学对应

| 内容 | 日常修改与观察 | 教学目标／功能编号 |
| --- | --- | --- |
| 技能参数 | 6 米范围、5 秒持续、6／4 秒冷却、20／30 点伤害作为 v0.1 基线；实验变体注明修改项及配置版本 | 数据与行为边界、时间条件，T04～T06、T12 |
| 目标规则 | 最近目标与标记优先是既定行为；新增行为由程序扩展，不能只改参数就假定支持 | 筛选、排序、确定选择；可比较直接分支与 Strategy 候选 |
| 标记与引爆表现 | 美术在约定内替换标记、倒计时与两类命中特效，不改变生效时刻 | 规则／表现分工、资源与清理，T13～T17 |
| 结果与徽记 UI | 显示胜利、失败或测试中止，本局获得量与测试身份累计量；开关不触发再次发奖 | 结果所有者、视图绑定、订阅作用域，T09～T11、T16 |
| 运行记录 | 能定位选中目标、标记截止、技能可用时间、消费结果、本局结果与奖励记录 | 可观察性、一次性操作与复现，T18 |

教学采用“直接方案 → 具体变化或失败 → 候选比较 → 实现与验证”。存在状态不意味着必须使用 GoF State，使用事件也不自动保证一次性结算；模式按实际变化选择。基线配置与实验变体分开，单项实验通过不替代 v0.1 双人验收。

| V09 处理顺序 | 相同目标分别执行 A→B 和 B→A | 前者引爆，后者不追补 B 伤害；T05～T06 |

| V11 冷却边界 | 冷却未结束与恰好结束时提交技能 | 前者拒绝且不延长原冷却，后者可在目标有效时成功；T05～T06 |
| V12 倒下与清理 | A 标记后倒下，再让目标倒下或标记自然到期 | A 不能再操作，既有标记先保留；目标倒下／到期时清理；T03、T05、T15 |

| V15 同步结束条件 | 在同一步规则更新内清空怪物并全员倒下 | 统一结算为失败，奖励均为 0；T09～T10 |
| V16 胜利奖励 | 一名玩家倒下，由队友清怪 | 两名参与者各获得 1 枚，本局与累计数量可辨认；T10、T16 |

| V21 两端与表现 | 两独立客户端观察同一操作，再替换兼容动画／特效／UI | 规则结果一致，表现替换不改时间或奖励；退出后无残留；T02、T13～T18 |

## 10. 状态与下一步

v0.1 已确认的是目标规则、A／B 参数、时序边界、胜负、测试中止与奖励语义。当前只有设计与网站页面，本文没有声称上述用例已通过。

普攻伤害与间隔、角色生命与移动速度、怪物属性与简单行为、怪物数量与出生点仍待确定；不从 B 的 20 点基础伤害推定普攻也为 20。镜头具体角度、输入映射、技术版本、坐标口径、服务更新与双客户端测试入口也由后续设计落实。

下一步先完成这些最小实现基线、配置字段、资源约定与观察入口，再按 P1 单项预览、P2 双人流程推进。需要调整已确认规则时记录版本与理由；不为了教学追加 Boss、成长或其他引擎开发任务。
