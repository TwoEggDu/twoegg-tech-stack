# Career Agent 化 Roadmap 设计说明

## 目标

在 Career 页面中增加一段面向未来的 Roadmap，说明下一步准备怎样把已经工程化的内容生产、质量检查与交付工作逐步 Agent 化。

这段内容需要同时满足两点：

1. 让招聘方看到未来方向建立在已有工程基础上，而不是临时增加一个 AI 标签。
2. 明确区分已经完成的工具链能力与尚未完成的 Agent 化计划，不把学习方向写成生产经验。

## 页面位置与叙事关系

Roadmap 放在「职业路径」之后、「技术证据」之前，页面阅读顺序调整为：

```text
过去的成果
-> 职业能力演进
-> 下一步 Agent 化方向
-> 已有技术证据
```

不修改 Hero 的主投定位，也不把 AI 放到首屏。Career 的当前主线仍然是多项目生产工具、客户端工程与交付结果；Agent 化只作为建立在这些能力之上的下一阶段。

## 标题与核心表达

英文眉题：

`Next Step / Agentization Roadmap`

主标题：

`把已经工程化的工作，继续变成可验证、可监督的 Agent 能力`

导语：

> 目标不是给现有工具套一层对话界面，而是把多年积累的规则、文档、工具和流水线，逐步整理成 Agent 能理解上下文、调用工具、提供证据并接受验证的研发基础设施。

## Roadmap 模型

采用成熟度阶段，不使用季度、年份、完成百分比或未经验证的交付承诺。

### 01 现有工程基础｜已具备

已经形成的内容：

- 导表与配置依赖校验
- 美术资源提交前检查
- 错误原因与修复文档绑定
- Jenkins 构建与交付流水线
- 跨项目共享资产与多平台 SDK 工具链

这一阶段不称为 Agent 化。它回答的是：未来的 Agent 可以建立在哪些真实、长期维护过的系统之上。

### 02 上下文与工具接口化｜下一步

准备把分散在工具、文档和流水线中的能力整理成 Agent 可使用的工程接口：

- 规则、依赖关系和修复知识可以被检索
- 导表、资源检查和构建状态可以被只读查询
- 工具输出形成结构化证据，而不只是一段日志
- 权限、项目范围和验证条件具有明确边界

这一阶段的重点不是模型能力，而是让既有工程系统变得可理解、可调用、可验证。

### 03 只读诊断 Agent｜计划推进

优先选择低风险、高复用的诊断场景：

- 配置与依赖错误诊断
- 资源提交问题解释与修复指引
- Unity / Jenkins 构建失败的证据收集和原因判断
- 跨项目接入时的规则与差异检查

默认输出应包含：失败位置、证据、可能原因、置信度和下一步检查。此阶段只给出判断与建议，不自动修改项目、不触发发布。

### 04 受控执行与跨项目复用｜长期方向

在只读诊断稳定并具备回归验证以后，再让 Agent 在人工审批下调用已有工具：

- 执行检查或生成修复建议
- 在明确白名单内应用可逆修改
- 触发构建、收集结果并完成回归验证
- 把在一个项目中成立的能力迁移到其他 Unity 项目

执行能力必须保留人工审批、权限边界、证据记录、失败停止和回滚机制。自动发布、无审批修改和不可追踪执行不属于当前 Roadmap。

## 内容与组件结构

Roadmap 文案继续放在 `data/career.yaml`，新增独立的 `roadmap` 数据块：

- `eyebrow`
- `title`
- `summary`
- `stages[]`
  - `number`
  - `status`
  - `title`
  - `description`
  - `items[]`
- `links[]`

`layouts/_default/career.html` 只负责渲染，不散落阶段文案。

Roadmap 末尾提供两个后续证据入口：

- AI 赋能：`/ai-empowerment/`
- Harness Engineering：`/harness-engineering/`

链接用于展示正在形成的方法与实践，不作为“Agent 化已经完成”的证明。

## 视觉设计

- 延续 Career 页现有色板、字体、边框和工程网格语言。
- 桌面端使用横向四阶段轨道；阶段之间有克制的连接线，不使用复杂流程图。
- 移动端变为纵向时间线，保持阶段状态和正文可读。
- 「已具备」与三个未来阶段使用不同但低饱和的状态标识，避免所有阶段看起来都已完成。
- 不使用模型 Logo、聊天气泡、机器人插画、粒子动画或 AI 渐变背景。

## 真实性与措辞边界

允许使用：

- 已具备
- 下一步
- 计划推进
- 长期方向
- 准备整理
- 逐步验证

不允许使用：

- 已完成 Agent 化
- 已落地智能体平台
- 自动修复生产问题
- 全自动交付
- 自主发布
- 已形成跨项目 Agent 平台

页面不得把 Roadmap 阶段写入 Hero 指标，也不得用未来能力替代现有成果。

## 不在本次范围内

- 不实现真实 Agent、聊天界面、MCP 服务或后台系统
- 不重构 AI 赋能或 Harness Engineering 系列
- 不修改现有文章正文
- 不增加季度承诺、进度百分比或虚构产出数据
- 不改变 Career 页当前主投职位

## 验收标准

- Roadmap 位于职业路径与技术证据之间
- 四个阶段的完成状态与未来状态能被快速区分
- 文案明确说明 Agent 化尚未完成
- 桌面端横向、移动端纵向均无溢出或遮挡
- AI 赋能与 Harness Engineering 两个内部链接可达
- Career 页面继续通过隐私信息和未验证数据扫描
- Hugo 完整构建无错误，浏览器控制台无新增错误
