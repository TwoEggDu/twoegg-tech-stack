# Career V0.1 设计说明

## 目标

在现有 TwoEgg Tech Stack 中增加 `/career/` 招聘入口。页面负责在 30 秒内讲清职业定位、问题范围、代表结果和验证路径；现有文章继续承担技术证据库的职责。

## 定位

- 主投：Unity 多项目生产工具负责人
- 兼容：Unity 客户端主程 / 客户端技术负责人
- 核心判断：能够对多项目内容生产、资产管线和客户端交付结果负责
- V0.1 不把 AI 作为主定位，不使用缺少来源的性能数字

## 信息结构

1. Hero：姓名、定位、三项已核实指标、生产架构缩略图与 CTA
2. 我解决的问题：跨工程内容生产、生产质量前置、自动化交付、多平台客户端工程
3. 代表性成果：每项严格按“结果 → 我的作用 → 证据”呈现
4. 职业路径：压缩最近四段经历，突出能力演进
5. 技术证据：把招聘结论路由到现有专栏或系列
6. 联系：只公开邮箱和 GitHub；完整简历通过邮件获取

## 视觉原则

- 复用站点现有字体、色板、Header、Footer、卡片、边框和间距变量
- Hero 延续现有深色工程风格，增强数字层级，但不引入新的视觉主题
- 桌面两栏、移动端单栏；不使用复杂动画、技能 Logo 墙或装饰性炫技
- 通过一条最小流程图表达“共享资产库 → 配置与依赖 → 四个独立工程”

## 真实性与公开边界

- 可用数字：10+ 年 Unity、4 个独立工程、1 套大型美术资产库、约 50 人协作
- 不公开：手机、微信、内部项目代号、内部 URL、服务器与 NDA 信息
- 证据链接只表述为“相关方法/工程实践”，不把通用文章伪装成具体项目复盘
- 当前没有脱敏公开简历 PDF，因此不创建虚假下载链接

## 验收标准

- `/career/` 与导航入口可用，站点构建无错误
- 桌面和移动端无明显溢出、遮挡或不可读内容
- 页面内部链接均能在构建产物中找到目标
- Career 构建产物不包含电话、微信、内部项目代号或未经确认的性能数字
- 只提交本页面白名单文件，不混入现有工作区草稿
