# Unity 游戏更新与发布系列规划

> 更新：2026-10-25。本文是本系列唯一的 canonical 篇级规划；根 doc-plan 只维护系列路由，各章节页维护正文或详细提纲。

## 目标与读者

面向已经接触 Unity 和资源管理，希望把更新系统连接到真实交付的客户端、构建发布维护者与技术负责人。

先从首次交付、线上修复、新英雄与活动说明为什么发生一次更新，再串联兼容关系、构建范围、启动检查、版本发布与恢复。概念先于工具命令；读者不必先读完 YooAsset 源码系列。

## 统一案例与名称

案例：客户端 100 首次交付 → 100 的配置、代码及资源修复 → 新英雄与活动 → 新底层能力要求客户端 101 → 决定强更与恢复策略。所有编号和事件先作为教学示例。

构建选项使用 Full / HotUpdate / Res / HotCode / Data。HotUpdate 构建三类热更内容，不等于自动发布；HotCode 仅覆盖可热更代码；文章名称不表示实际项目枚举已修改。

## 资料与验证边界

本轮机制对照阅读日期为 2026-10-23：YooAsset 官方 3.0.x 文档、Addressables 2.7 页面（显示 2.7.6）、HybridCLR 官方 9.x 文档，以及 CCD、Remote Config、Google Play 官方说明。它们用于核对设计边界，不代表实际项目采用这些版本；各章正文必须再次固定工程版本、源码及平台适用范围。资料链接随相关章节保存。

文档验收包括：七篇顺序不变，正文与提纲标记符合实际状态，示例与第 04 篇契约一致，Hugo 构建成功，章节链接与锚点有效，首页相关专题保留。工程验收需另做：组合接受/拒绝、基线不匹配、数据下载中断、加载后失败、灰度分组、目标客户端不可得及分层恢复实验。

## 待核对的工程问题

- 业务清单里最新版本、最低兼容版本和逐包强更目标的真实语义，是否存在隐式回退到最新策略。
- 资源构建的目标客户端选择、版本继承、平台与 Profile 基线是否一致。
- 现有构建、编辑器和公网发布器能否完整保留三类内容版本，是否真正支持资源独立发布。
- 小游戏平台的旧包拦截与实际新包下载、应用或重启是否闭环。
- 已安装新客户端、数据格式及服务端变化对回退的限制。
- 组合准备记录的中断一致性、缓存策略有效期与当前准入要求，是否可能混用新旧内容。
- 灰度人群是否稳定，发布策略并发修改与缓存传播如何处理，客户端是否上报实际采用组合。

这些是后续取材与验证问题，不在提纲阶段宣称已修复或已验收。
