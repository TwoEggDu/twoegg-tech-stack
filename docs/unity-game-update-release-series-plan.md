# Unity 游戏更新与发布系列规划

> 更新：2026-10-23。本文是本系列唯一的 canonical 篇级规划；根 doc-plan 只维护系列路由，各章节页维护详细提纲。

## 目标与读者

面向已经接触 Unity 和资源管理，希望把更新系统连接到真实交付的客户端、构建发布维护者与技术负责人。

先从首次交付、线上修复、新英雄与活动说明为什么发生一次更新，再串联兼容关系、构建范围、启动检查、版本发布与恢复。概念先于工具命令；读者不必先读完 YooAsset 源码系列。

## 入口与边界

- 主导航：顶部“工程与交付”主题页的“选择一个系列”；同时保留交付工程栏目页入口。
- 主栏目：交付工程。公开首页：[Unity 游戏更新与发布](../content/delivery-engineering/unity-game-update-release-series-index.md)。
- YooAsset 首页提供完整流程入口，原八篇源码主线及导读保持顺序。
- 复用包体分发、脚本热更、平台发布和线上运营专题，不复制它们的完整目录。
- 具体章节按通用问题、抽象模型、Unity 实现和工程边界展开。示例先脱敏，不写入项目路径、账号、内部地址、配置秘密或未公开的原始业务材料。

## 统一案例与名称

案例：客户端 100 首次交付 → 100 的配置、代码及资源修复 → 新英雄与活动 → 新底层能力要求客户端 101 → 决定强更与恢复策略。所有编号和事件先作为教学示例。

构建选项使用 Full / HotUpdate / Res / HotCode / Data。HotUpdate 构建三类热更内容，不等于自动发布；HotCode 仅覆盖可热更代码；文章名称不表示实际项目枚举已修改。

## 写作顺序与验收

1. 首页与七篇可访问提纲先形成稳定入口，链接和章节顺序验证后逐篇写正文。
2. 01～03 以业务场景建立判断；04 固定示例版本契约；05～07 再展开构建与运行、发布。
3. API 与机制按所用 YooAsset、Unity、平台和热更方案的固定版本核对；不直接把旧项目调用复制为新版接口。
4. 各章分别记录源码核对、示例设计、实验和设备验证，未执行不标通过。
5. 正文完成时先更新本文状态，再按需更新首页；根 doc-plan 不维护篇级清单。

## 待核对的工程问题

- 业务清单里最新版本、最低兼容版本和逐包强更目标的真实语义，是否存在隐式回退到最新策略。
- 资源构建的目标客户端选择、版本继承、平台与 Profile 基线是否一致。
- 现有构建、编辑器和公网发布器能否完整保留三类内容版本，是否真正支持资源独立发布。
- 小游戏平台的旧包拦截与实际新包下载、应用或重启是否闭环。
- 已安装新客户端、数据格式及服务端变化对回退的限制。

这些是后续取材与验证问题，不在提纲阶段宣称已修复或已验收。
