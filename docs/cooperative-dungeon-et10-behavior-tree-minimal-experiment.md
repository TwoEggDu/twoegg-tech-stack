# 无尽对决行为树最小接入实验：版本、节点、导出与验证

日期：2026-10-25（Asia/Shanghai）

> 实验设计已确认 · 待实施、待验证。本文规定首个近战怪接入实验的目标基线、节点、配置导出与 E0～E6 步骤，没有执行编译、制作导出或运行游戏。ET10 内置行为树仍为首选候选，尚未采用为正式实现。文档与网站构建检查不属于本实验运行证据。

## 1. 实验范围与采用方式

首轮复用 ET10 现有 BuffTick 周期驱动与 Spell／Buff 配置导出，补充少量同步业务节点，先在服务端验证选敌、追击、等待与攻击，再接 Editor 观察。不改核心行为树框架，不另建通用图编辑器，不迁移整个项目或引入其他引擎开发。

备选是另建专用 AI 调度／导出，或使用现成长期协程追击节点。前者提前增加工具建设，后者与本次最近选敌、地面中心距离和直线移动的规则不一致，故首个实验选择复用周期宿主、编写同步叶子。若验证发现现有链路需要大量适配，再回到 [ET10 行为树候选评估](cooperative-dungeon-et10-behavior-tree-evaluation.md) 比较成本与回退，不把候选改成强制依赖。

一个测试局包含两名测试玩家和 3 只近战怪，沿用 [最小玩法规则 v0.1](cooperative-dungeon-minimal-gameplay-rules-v0.1.md) 的基础参数与出生点。本轮不接正式登录、匹配、A／B 技能和测试奖励系统；这只限定首轮实验范围，不删除正式 v0.1 的规则。单项通过后，再回归完整双人流程。

## 3. 周期驱动、时间与状态所有权

首轮建议 BuffTick 决策间隔为 50 毫秒。它是已选实验参数，不是为整个游戏提前确定网络同步频率。节点每次完成一个同步查询或动作，不启动长期追击、等待协程。

| 数据或责任 | 首轮约定 |
| --- | --- |
| 当前时间 | 由服务端权威规则时间提供，统一使用毫秒；测试入口可提供受控时间，业务节点不各取一套钟 |
| 首次攻击 | 怪物的 `NextAttackAt` 初始化为本局运行开始时间加 2000 毫秒 |
| 后续攻击 | 成功攻击后将 `NextAttackAt` 设为本次规则时间加 2000 毫秒；不按旧截止时间积攒补发攻击 |
| 换目标与切分支 | 不修改 `NextAttackAt`；树重复调用也不提前恢复攻击 |
| 移动 | 按规则更新的实际时间差以 2 米／秒推进，只有一个移动执行者；不能叠加旧追击协程或另一套位置推进 |
| 距离 | 地面中心距离，忽略高度，不扣除碰撞半径；近战边界为 1.5 米 |
| 运行上下文 | 树定义共享，每只怪独立持有目标和决策上下文；生命、冷却由业务战斗状态拥有 |
| 停止与重开 | 明确的生命周期拥有者停止调度和移动、清理上下文；不依赖一个没有被执行的树分支做清理 |

BuffTick 可能在建立周期调用前先调用一次树；开局首次决策不能等同于立即允许攻击，首次 2000 毫秒门槛仍由战斗状态约束。具体服务端规则循环、调度注册和调用顺序在实施时接入并记录，不能因选择 50 毫秒间隔而假定时间边界已经正确。

Buff 只是复用已有驱动链路的实验宿主，不把“怪物 AI 就是 Buff”写成项目领域规则。本轮不把 ET10 的协程节点引入这棵树，若以后需要长期动作，再单独验证取消、实体有效性和上下文生命周期。

## 4. 节点清单与树结构

复用现有 Sequence、Selector、Not 和周期根节点 `EffectServerBuffTick`。下列 9 个名称是实验拟新增的业务节点，均待实现，不是宣称 ET 已提供的 API。节点薄封装查询、移动与战斗规则，不将通用移动或战斗系统塞进行为树包。

| 节点 | 类型 | 输入、输出与职责 |
| --- | --- | --- |
| MeleeCanAct | 条件 | 输入本局和怪物状态；仅在本局运行且怪物存活时满足 |
| SelectNearestAlivePlayer | 同步动作 | 查询同局存活玩家，按地面距离及同距实例 ID 选目标；无目标时清空目标并完成查询 |
| HasTarget | 条件 | 检查当前选择是否为有效目标，供无目标分支使用 |
| TargetInMeleeRange | 条件 | 检查目标地面中心距离不超过 1.5 米 |
| StopMovement | 同步动作 | 停止当前怪物移动，完成本次动作 |
| AttackReady | 条件 | 比较当前时间与业务状态中的 NextAttackAt，不能修改冷却 |
| TryMeleeAttack | 同步动作 | 调用战斗规则校验本局、双方状态、距离和冷却，成功才扣 10 血并推进冷却；记录成功或拒绝原因 |
| MoveTowardTargetStep | 同步动作 | 通过唯一移动执行者以 2 米／秒推进本步；不穿过近战停止距离，也不越过场地边界 |
| WaitDecision | 同步动作 | 记录正常等待并立即完成，不创建计时器、协程或额外冷却 |

树的语义结构如下，尚未生成实际图资产：

```text
Sequence
  MeleeCanAct
  SelectNearestAlivePlayer
  Selector
    Sequence：没有目标
      Not(HasTarget)
      StopMovement
    Sequence：目标在近战范围内
      TargetInMeleeRange
      StopMovement
      Selector
        Sequence
          AttackReady
          TryMeleeAttack
        WaitDecision
    MoveTowardTargetStep
```

### 4.1 返回结果与失败边界

实验自定义条件以 0 表示满足、约定非零表示不满足，接入时采用与现有组合节点相容的映射。它不是引入通用 `Running/Success/Failure` 持续节点模型。

正常动作完成后返回 0，使当前 Selector 分支处理完成。SelectNearestAlivePlayer 在无候选时也完成查询，让后续无目标分支明确停止移动。TryMeleeAttack 的“完成攻击尝试”与“造成伤害”分开记录；规则拒绝不得重复攻击或误落入追击，也不得修改冷却。

范围内冷却未好时，AttackReady 条件不满足，随后 WaitDecision 正常完成，不能让外层 Selector 落到 MoveTowardTargetStep。缺失配置、错误类型和执行异常必须单独报错、停止本次决策并留下诊断，不能伪装成普通条件不满足后继续回退。

已有 AI_MonsterZhuiJi 按仇恨选择目标、扣除双方半径并使用寻路协程，与本实验不同。它保留为阅读对照，不直接挂进这棵树，也不为复用现有节点而改变 v0.1。

## 5. 配置源、导出和采用

首轮管线为：Buff 配置资产 → 周期根节点与近战树 → 结构和引用校验 → 保存 → 完整候选配置代码导出 → 完整构建 → 服务端加载与版本确认。

1. 在现有配置命名空间查重后分配独立实验 ID，记录 ID、源资产与树身份；不覆盖已有示例。本文没有创建资产或预分配实际 ID。
2. 复用已有 Spell／Buff 图资产和配置工厂生成入口，验证周期根与新增节点能被检查、保存和重新加载；不假定任意 AI 根都能导出。
3. 三只怪复用树定义，分别建立运行上下文和战斗状态，不能共享一份可变目标或冷却。
4. 图配置与 Luban 参数确定唯一权威来源和引用关系；同一数值不能在两处分别维护。实验先只覆盖当前导出链路，不为讲配置而另建编辑器或重复导出体系。
5. 导出后按源码差异核对实际生成物与其适用运行模式，不手改生成代码；失败不采用半套数据。生成成功也不能代替服务端实际加载验证。
6. 用源资产、导出产物、源码与配置版本关联到运行记录。若既有入口无法支持最小树，停止本路径并登记缺口，先评审最小适配，不把大量工具开发隐藏在“导出配置”一步。

实施时遵循固定版本的包与程序集规范：业务节点放入允许依赖相应能力的扩展层，编辑器与运行时分开；不让基础包反向依赖业务包、不手工改 csproj 或生成 meta。本文不新增包、节点代码或配置制品。

### 5.1 固定版本的导出入口与检查点

本次静态核对的入口是 Editor 菜单 `ET/Map/ExportScriptableObject`（F3）：`ExportScriptableObjectEditor` 收集 Spell／Buff 资产，再调用 `BTConfigCodeExporter`。首轮使用其中的 Buff 资产承载周期树，不能拿一棵独立 AI 根保存成功来替代这条导出验证。

当前生成方向为 spell 包 `CodeMode/Config/{Client,ClientServer,Server}/Config` 下的配置工厂 C# 代码，并刷新资产。实施时记录完整菜单操作、源资产位置、实验 ID、实际变化的生成文件及运行模式；不假定三个目录都必须产生同样内容，也不提前填写不存在的文件名。源资产保存、配置代码生成、完整编译、服务端按 ID 加载，是四个分别检查的环节。

该入口扫描全部相关图资产，并可能修复零值或重复 TreeId 后保存，不能假设只处理选中的实验树。实施时使用隔离的实验副本，导出前保留源资产和生成物差异，导出后逐项检查 ID 修复与其他示例的变化；发现非预期改动先停止核对。确认没有覆盖其他示例或遗留旧定义；重新打开源资产和重新启动实验加载入口后，核对同一树身份与参数。如果导出器没有收集该资产、找不到业务节点或服务端仍加载旧配置，E1 不通过，不能靠手改生成代码继续运行。
