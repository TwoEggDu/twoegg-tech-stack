# 游戏产品证据与决策系列规划

> 2026-10-14；唯一主规划。状态：仅规划，四篇候选均未写正文、未做研究或实验。来源范围与归并依据见[跨仓审查](game-lifecycle-coverage-audit.md)。

## 定位与边界

服务制作人、策划、用户研究、发行及技术负责人，回答同一条决策链：为什么值得做 → 玩家是否理解并愿意玩 → 如何进入市场 → 是否值得持续投入。

本轮按标题、目录和代表正文核对，现有技能系统讲执行机制，Bug/Playtest 讲版本风险，平台发布讲技术交付，虚拟经济讲资产与交易；它们都不能单独承担这条产品证据链。全站扩展规划中的“游戏系统设计”“Playtest 与玩家体验验证”属于早期建议；本系列仅接管下面四个明确缺口，不接管旧建议中所有篇目。

新建一个系列，是因为它有持续的决策主线、独立读者和多篇问题边界；不按学习库 G11～G14 逐一建系列，不把生命周期地图变成篇级计划。这里的投资判断仅指游戏项目分阶段投入研究，不给收益承诺。

## 候选提纲

编号 `GPD-01～04` 仅用于本规划，不预占文章 URL、slug、series 或 weight。以下三级小节为研究问题，不是结论或教程。

<a id="gpd-01"></a>

## GPD-01｜从市场假设到立项门槛：什么证据值得下一笔投入

- **主问题**：市场机会、玩家需求、制作能力和现金需求，怎样共同支撑继续、转向或停止？
- **责任边界**：研究证据与投入门槛；人员授权回工程判断，CPU/GPU 预算回性能系列，不把技术预算当财务预算。
- **前置**：基本产品研发语境；无其他候选篇硬前置。GPD-02 的原型结果是后续反馈。
- **可复用文章**：[工程健康度](../content/essays/engineering-health-metrics.md)、[性能预算总论](../content/performance/game-budget-00-overview-why-budget-management-fails.md)，分别提供组织与制作约束，均不充当市场研究。
- **所需证据**：有日期和口径的公开市场/竞品资料、授权访谈摘要、团队产能样本、成本区间及现金流情景；缺失数据保留未知，不编造预测。
- **当前状态**：仅规划，未写正文；市场资料、财务假设和投资判断均未核实。

### 机会与反证

怎样界定目标品类、平台、地区、玩家和竞品样本？哪些观察会推翻需求或差异化假设？

### 制作可行性与投入上限

原型、垂直切片分别要消除哪些风险，内容产能怎样估计？怎样区分运行预算、研发费用、发行成本及退出成本？

### 阶段评审与停止条件

怎样把证据来源、未知项、负责人、投入上限和复核时间写入决策记录？反证出现后谁决定暂停或改变范围？

<a id="gpd-02"></a>

## GPD-02｜玩法原型怎样成为玩家研究：从核心循环到可玩性证据

- **主问题**：玩家的选择、理解、节奏和动机是否符合体验目标？
- **责任边界**：玩法原型与用户研究的方法和证据；设计机制主线引用 [GamePlay](gameplay-series-plan.md)，不重复技能执行、Bug 分诊或完整游戏设计教材。难度、公平与经济奖励只研究体验交点。
- **前置**：明确目标玩家与待验证体验假设；不要求先读完整服务端系列。
- **可复用文章**：[Bug 与 Playtest](../content/code-quality/bug-management-and-playtest.md)、[技能总索引](../content/system-design/skill-system-series-index.md)、[玩法规模与性能](../content/performance/game-performance-design-scaling-risk.md)。
- **所需证据**：经授权的研究招募条件、任务脚本、观察编码、匿名反馈与反例、原型版本和复测目标；没有招募或原型结果时只写研究设计。
- **当前状态**：仅规划，未写正文、未招募、未实验。

### 体验目标与循环模型

核心循环、长期循环、反馈奖励和关卡节奏分别解释什么？怎样避免把奖励驱动、留存或没有 Bug 直接当作乐趣证据？

### 原型与观察设计

何时用纸面原型、交互样机或垂直切片？参与者选择、观察任务、新手引导和无障碍需求怎样影响解释？

### 研究反馈到研发需求

哪些发现需要修改规则、表现、引导或技术预算？怎样把观察、解释和设计建议分开，形成可复测的 GDD 变更？

<a id="gpd-03"></a>

## GPD-03｜从可发布版本到市场发行：渠道、增长和 Soft Launch 的证据门槛

- **主问题**：产品应该进入哪个市场，以什么渠道和投入规模验证增长？
- **责任边界**：市场发行、自发/合作发行、触达和社区；技术灰度归交付，因果方法归长线运营，合同与平台义务只列研究项。
- **前置**：GPD-01 的目标市场和投入边界；平台发布、产品实验按问题延伸，不构成循环硬前置。
- **可复用文章**：[平台发布索引](../content/delivery-engineering/delivery-platform-publishing-series-index.md)、[灰度放量](../content/delivery-engineering/delivery-release-operations-01-canary.md)。二者证明技术路径已被讨论，不证明获客成功。
- **所需证据**：可公开的渠道资料、标明日期的商店/平台官方文档、授权合同摘要、创意与用户匹配资料、匿名 cohort 和归因口径；无真实投放数据不写增长效果。
- **当前状态**：仅规划，未写正文、未投放或上架。

### 市场与渠道组合

自发、发行商合作和不同商店渠道怎样比较权责、成本和触达？商店素材、社区、媒体、创作者与客服各交付什么？

### 获客与归因边界

怎样区分自然增长、付费归因和真正增量？CAC、LTV、ROAS 的窗口、分群、成本口径与不确定性怎样保持可比？

### Soft Launch 与持续触达

软启动要检验哪些市场假设，如何与技术容量和质量放行共同决定 Go/No-Go？玩家反馈、流失与召回怎样回到产品和内容产能评审？

<a id="gpd-04"></a>

## GPD-04｜从虚拟经济到持续经营：收入、体验和成本怎样共同复盘

- **主问题**：商业模式与商品设计是否维护长期体验，版本收入是否足以支持持续服务？
- **责任边界**：经营假设和产品取舍；货币账本、发货/退款实现回服务端，数据实验回长线运营，不把入账、流水、利润或现金混称收入。
- **前置**：GPD-01 的成本情景、GPD-02 的体验目标；具体统计知识按需补齐。
- **可复用文章**：[虚拟货币](../content/system-design/game-backend-economy-01-currency-design.md)、[道具发放与回收](../content/system-design/game-backend-economy-02-item-distribution.md)、[支付](../content/system-design/game-backend-economy-04-iap-payment.md)。这些已有正文需先处理审查报告登记的问题。
- **所需证据**：脱敏订单/退款与结算口径、内容和服务成本、商品与经济产消模型、分群体验指标、财务口径复核；不填无来源价格、回本周期或收益率。
- **当前状态**：仅规划，未写正文、未获取真实经营数据。

### 商业模式与体验护栏

买断、订阅、F2P 或混合模式各自约束哪些体验和持续服务承诺？定价、产消、通胀、付费公平怎样成为可研究假设？

### 收益与成本分账

怎样连接交易、退款、渠道结算、税费待核项、服务器/CDN、内容生产和客服成本？哪些数字尚不可比较？

### 长期迭代与退出输入

短期转化提升是否牺牲留存、信任和未来内容空间？怎样把有条件的经营结论交回立项评审或退役规划？
