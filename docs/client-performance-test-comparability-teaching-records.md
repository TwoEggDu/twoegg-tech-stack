## 2. 先固定要回答的问题

贯穿任务是打开一个界面并触发一次特效。本材料只提供两种观测：

- **应用间隔**：同一个应用循环标记的相邻时间戳之差，可能含等待。
- **请求到应用就绪**：请求发出到本次界面与特效的逻辑状态已提交、可供约定后续阶段消费的时间。它是业务代理终点，不代表已经完成绘制、呈现或屏幕反馈。

时间单位统一为 ms。每次运行使用自己的单调时间域，只在同一次运行内相减；跨运行比较的是相同定义的时长，不相减绝对时间戳。GPU 和显示数据均未提供，保留“未测”，不填零。

每组分别回答三个层次的问题：记录中的数值有什么差异、条件是否允许用于指定比较、是否足以接受优化。不同问题可以得到不同结论。

## 3. 第一组：长窗口接近，不代表首次事件相同

### 3.1 教学条件与完整输入

候选 A/B 仅改变一项创建实现，任务输入、必要表现和逻辑完成条件相同。相机、背景、分辨率、画质、运行载体、平台、采集配置及起始状态相同，作为本题明示前提。实际项目仍需证据证明这些条件，不能靠两个同名档位证明配置一致。

每个候选各一轮新进程运行；资源输入按同一教学协议预先就绪，目标实例未创建。这里的“首次”指该进程中首次打开本界面，不指磁盘、驱动或系统全局缓存全部为空。缓存等条件在本题中假设一致，不承诺真实平台可精确重置。

| 项目 | 记录 A：`A-run-1` | 记录 B：`B-run-1` |
| --- | --- | --- |
| 应用循环边界 `t0` | 0 | 0 |
| 第 1 个应用间隔 | 64 | 48 |
| 第 2–100 个应用间隔 | 各为 16，共 99 个 | 各为 16，共 99 个 |
| 首次请求 `q1` 的请求/应用就绪时间 | 0 / 90 | 0 / 74 |
| 同进程重开 `q2` 的请求/应用就绪时间 | 2000 / 2018 | 2000 / 2018 |
| 应用间隔窗口 | 从 `t0` 起完整的前 100 个间隔 | 同一事件与计数口径 |
| 请求窗口 | `q1`、`q2` 分别保留 | `q1`、`q2` 分别保留 |

上表是完整的压缩输入，可以展开而不补造数据：`t_i = t_(i-1) + d_i`，`i=1..100`；100 个相邻间隔需要 101 个边界时间戳。每条间隔用“运行身份 + 循环标记 + 结束边界编号”标识，不能把相同数值视为重复记录。`q2` 在前 100 个间隔窗口之外，不能混进首开窗口。

应用间隔既不是屏幕间隔，也不是该特效的独占成本。它包含整个应用在选定窗口内推进的结果。

### 3.2 算法与可复算结果

本例分位数采用 nearest-rank：升序后，`Pp = x_(ceil(p × N))`，位置从 1 开始，不插值。只用来演示口径；其他工具采用不同算法时应先对齐。

| 指标 | A | B | 能说明什么 |
| --- | --- | --- | --- |
| 100 个间隔的覆盖时长 | `64 + 99×16 = 1648` | `48 + 99×16 = 1632` | 选定窗口的时长 |
| 平均应用间隔 | 16.48 | 16.32 | 均值相差 0.16，不能代替首次事件 |
| P95 / P99 | 16 / 16 | 16 / 16 | 第 95、99 个顺序统计量没有覆盖唯一的最大值 |
| 最大应用间隔 | 64 | 48 | 本记录最长间隔相差 16；原因尚需关联证据 |
| 首次请求到应用就绪 | 90 | 74 | 代理终点的时长相差 16 |
| 同进程重开到应用就绪 | 18 | 18 | 两次记录里的重开时长相同 |
| 第 2–100 个间隔的均值 | 16 | 16 | 所列后续样本相同，不证明长期稳态表现 |

均值的相对变化为 `(16.48−16.32)/16.48 ≈ 0.9709%`；首次代理时长的相对变化为 `(90−74)/90 ≈ 17.7778%`。分母和对象不同，不能换成同一个“性能提升百分比”。

**本组判断：** 在明示教学条件下，可以描述 A/B 的同口径记录差异，也可以分别比较首开、重开与后续间隔。P95/P99 相同不等于首次没有差异；均值只差约 1% 也不等于首次代理时长只差约 1%。

每个候选只有一轮运行，连续 100 个间隔共享该轮缓存、调度和状态，不能宣称有 100 次独立运行；`q1/q2` 也不是两次相同初始状态的独立重复。本组没有运行间波动、显示反馈、资源代价或实际接受条件，不能据此接受真实优化或更新项目基线。数值相差同为 16 也不能证明最长间隔导致了全部代理时长差异。

## 4. 第二组：报告更快，但任务状态和采集条件变了

### 4.1 条件差异先于汇总

| 条件 | 记录 A | 记录 B |
| --- | --- | --- |
| 候选 | A | B |
| 请求结构 | 四轮新进程各一次首开 | 同一进程预热后连续四次重开 |
| 起始资源/实例 | 目标实例未创建；资源状态按首开协议记录 | 资源保留且实例池可复用 |
| 实际渲染尺寸 | 1920×1080 | 1280×720 |
| 采集配置 | 详细诊断模式 | 仅业务事件的较少插桩模式 |
| 热与背景状态 | 未提供足以对齐的记录 | 未提供足以对齐的记录 |
| GPU/呈现证据 | 所需数据未提供 | 所需数据未提供 |

这是人为构造的“同时改变多个条件”记录，不指定某个引擎的真实开销。详细模式可能改变时间和内存占用；差额不能统一当成一个可直接扣除的常数。

### 4.2 保留请求总数、超时与缺失

仍使用相同的请求/应用就绪事件定义，起始时间在各自运行的单调时钟中记为 0。B 的四次请求分别使用各自请求时刻作为相对零点。

| 记录/运行/请求 | 应用就绪时长 | 任务与证据状态 |
| --- | --- | --- |
| A / `A-run-1` / `q1` | 90 | 成功，两个端点齐备 |
| A / `A-run-2` / `q1` | 94 | 成功，两个端点齐备 |
| A / `A-run-3` / `q1` | 不填精确值 | 教学驱动在 500 时触发超时；此前持续观测中未见应用就绪事件，业务最终状态未知 |
| A / `A-run-4` / `q1` | 缺失 | 事后功能检查确认成功，但就绪事件丢失，无法计算时长 |
| B / `B-run-1` / `q1` | 18 | 成功，两个端点齐备 |
| B / `B-run-1` / `q2` | 19 | 成功，两个端点齐备 |
| B / `B-run-1` / `q3` | 20 | 成功，两个端点齐备 |
| B / `B-run-1` / `q4` | 21 | 成功，两个端点齐备 |

500 是本题的观察截止约定，不是建议采用的性能阈值。超时记录能支持“截至截止时未观测到目标”，不能填成恰好 500 完成。对该代理事件，可按右删失记录保存观察下界及条件；最终时长仍未知。若连截止前的观测连续性也无法保证，就应改记证据不足，不能沿用这个下界。

可观测成功样本的均值是 A=`(90+94)/2=92`，B=`(18+19+20+21)/4=19.5`。这个算式没有计算 A 的四次请求总体均值，也没有证明 A 的全部业务成功率。A 有 4 次尝试：2 次成功且计时完整、1 次测试超时、1 次业务成功但计时缺失。B 是同一轮运行内 4 次成功请求，不是 4 次独立运行。

**本组判断：** 已观察成功样本的数值可以按限定身份描述；这些记录不满足“同一首开负载下，改动 B 带来多少收益”的比较条件。实际状态、尺寸、采集和样本结构同时改变，无法把差额归给创建实现。A 的全请求时长分布、B 在相同首开条件下的表现，以及具体画面反馈都属于证据不足。

不能通过把缺失填零、超时填 500、删除未成功请求，或从 A 的数字中减去估计的采集开销来修复。应先定义要比较首开还是重开、诊断还是接受配置，设计同条件记录；缺失和超时另查原因并保留。知识阶段只完成这个补测设计，实际补测留到实践阶段。

## 5. 理解检查与改选条件

| 问题 | 答案应包含的判断 |
| --- | --- |
| 第一组 P99 相同，能否说首次操作没有变化？ | 不能。明确分位数位置，另看首次请求窗口与最大间隔，保留代理/显示边界 |
| 把应用窗口延长为 1000 个间隔，新增均为 16，会怎样？ | A/B 均值分别为 16.048/16.032，差值缩到 0.016；已记录的首次代理时长仍为 90/74，改变窗口没有重做事件测量 |
| 100 个间隔是不是 100 次独立验证？ | 不是。先按运行/请求/帧区分层次，保留运行间变化；帧数不能充当独立重复次数 |
| 导入时同一帧记录出现两次怎样处理？ | 按运行、来源和帧身份检查重复；相同数值的不同帧必须保留。先查导出/合并规则，不仅按时长去重 |
| 第二组只把分辨率对齐，能否宣布收益？ | 仍不够。首开/重开、资源/实例状态、采集方式与运行结构等差异仍在 |
| 超时和计时缺失都应算作业务失败吗？ | 不能。测试截止、业务结果和证据有效性分别记录；完整观察的未完成与丢失终点不能混同 |
| 是否规定统一的三次或十次重复？ | 不规定。按后续实际波动与决策要求设计重复，保持阶段和记录完整；本材料没有足够数据计算可靠置信区间 |
| 详细采集更全，是否可以直接替代接受配置？ | 不自动替代。先核对观测范围与扰动，采集配置改变后保留另一组身份，并设计较低扰动的复核 |
