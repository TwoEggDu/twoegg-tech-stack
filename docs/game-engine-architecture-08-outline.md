拟题：**用同一组问题读懂两台引擎：对象、模块与工具怎样组织**。
状态：2026-10-25重定范围，只有提纲，未起草正文。篇级状态由[canonical plan](game-engine-architecture-series-plan.md)维护。

## 主问题

遇到同一项需求，怎样在Unity与Unreal中定位状态、接口和变更传播，而不是只把两个API名放在一行？读者完成本文后，应能拿着相同问题进入两台引擎，各自画出有证据支撑的路径。

撤下原“Unity偏workflow，Unreal偏framework”的总判断。Package、Plugin、World、Prefab等名字可以成为查证入口，不能从命名或文档篇幅推出整台引擎的架构性格。

## 正文结构建议

1. 从一个相同任务进入，先给共同问题清单，不先给产品标签。
2. 定义公共模型：输入、状态持有、调用/数据交接、失败与清理；图先标箭头语义。
3. 任务一：Unity路径、UE路径、不能一一对译的具体原因。
4. 任务二：工具/构建/运行三种环境的接点；可选任务三视篇幅决定。
5. 将观察回填00/00A地图：哪些是共同责任，哪些是版本与项目选择。
6. 自检：替换一项需求，让读者指出应查的文档或实现位置；深入内容链接原专题。

不再套固定八段，也不要求Unity和Unreal等长。每项差异必须由所选任务的证据产生，不能用“更轻、更强、更加框架化”收尾。
