## 最终结构与取舍

1. 相同业务任务先固定单位、交付范围和完成条件，再提出输入、状态、接口、产物、失败和清理问题。
2. 警戒参数：分别追Unity序列化字段/Prefab实例覆盖/编辑保存，以及UE反射字段/组件模板/实例/编辑事务；配置与倒计时分开。
3. 外观交付：同样采用随初始版本交付；Unity用Resources的小例子，UE用目标关卡引用与Cook，随后回到共同故障检查表。
4. 工具隔离：给外观增加编辑器检查按钮，只展示Package/程序集与Plugin/模块的组织区别及Editor→Runtime代码依赖，不另开第三套专业能力实例。
5. 三组最小验证收束：配置覆盖、运行消费、目标交付与工具隔离；明确这些是实验设计。

撤下原“Unity偏workflow、Unreal偏framework”的结论。Prefab/Blueprint Class、Package/Plugin、程序集/模块只按所需职责比较，不逐名对译。正文两段声明是自拟片段，两张图分别为数据关系与代码依赖。
