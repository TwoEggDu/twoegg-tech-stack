# D2D 首页与主要入口调整记录

日期：2026-11-06。本文是本轮入口审查与本地验证记录，定位原则仍由 [站点定位](site-entry-and-audience-plan.md#column-core-principles)维护，不建立新的系列目录。

## 本轮范围

检查线上首页，并对照本地首页、作者说明、研发总览、技术目录、工程与交付、FDE、生产实践、质量与性能入口。属于主要阅读入口的抽查，不代表逐篇审校全站文章。

作者明确的责任与目标是：对最终交付的游戏质量负责，深入美术、策划、程序的生产现场解决堵点，尽可能将运行问题在生产中暴露、修正与复验，使每一步产出尽量符合上线要求。D2D 表示从设计到交付的生产主线，FDE 表示深入现场推动落地的工作方式。

首页展示职责、工作哲学和持续反馈过程，再逐步引入具体专栏。技术组合与实现细节保留在作者说明及深入专题中；完整管线仍作为建设目标，具体机制与结果分别说明。

## 发现与处理

| 入口问题 | 本轮处理 |
| --- | --- |
| 首页从“内容做好以后”切入，容易把质量工作放到制作结束之后 | 首屏说明游戏质量责任与工作哲学，随后呈现现场观察、问题前移、能力沉淀 |
| 首页缺少持续反馈的工作方式 | 用质量目标关系图连接协作、生产、持续性能与交付，并简述日常检查、定期验证和修正复验 |
| 交付栏目以内容冻结为起点，双端与设备描述容易形成后期介入的印象 | 扩为从制作、功能研发与交接开始，对齐生产中的标准与验证 |
| 作者、研发总览与 FDE 入口尚未集中表达此次责任与目标 | 补充 D2D 主线、工作方式和质量前移，保留具体案例的历史职责和验证边界 |
| 技术目录缺少方法与生产体系的直接入口 | 增加既有 FDE 与客户端生产体系链接，保留领域目录职责 |
| 质量索引中的“完整防线”等措辞容易扩大模型覆盖范围 | 改为分层技术质量检查，明确整体体验和目标环境仍需联合验收 |
| 性能入口需要承接持续自动化的工作方式 | 增加体验目标、持续观测、诊断验证与回归的说明，保留原理与具体引擎的深读路径 |

## 首页阅读顺序与样式

1. 首屏：用简短介绍与侧栏理念说明质量责任，以及让各工种专注生产的工作哲学。
2. 工作方式：现场观察、日常检查、功能与性能验证、修正复验；用中心质量目标与四个问题入口同时解释关系和引导阅读。
3. 先读一篇：以资源交接问题与生产体系总览连接具体实践。
4. 综合项目实践：将“无尽对决”的独立入口放在首页内容区最下方、页脚之前，连接玩法、内容制作、协作与验证；首页只呈现设计、实现与验证状态，具体技术路线在项目内展开。

根据作者本轮视觉反馈，恢复接近原首页的紧凑体量、蓝灰色、细字重衬线标题和文字链接。合并重复的理念说明，取消大号双色口号、实心按钮和整段深色背景，把唯一较强的色块留给关系图中心。具体框架与工具名称不出现在首页正文中；原有文章 URL 与专栏保留，“无尽对决”继续作为首页综合项目入口。
