1. 为什么改贴图牵动场景/设备、加平台影响多个目录；职责、编译/模块依赖、运行调用、数据流与线程分别画。
2. 四层主线与共享服务的参考图，箭头为接口/代码依赖，Core直接依赖可省略，允许合理跨层。
3. 每个部分的输入输出、持有状态、典型职责与越界行为。
4. 为什么Framework要从Function中拆出：世界组织与生命周期，与渲染/物理算法分别负责。
5. Core与平台实现的关系；接口归属、注册/注入和反向回调不混成双向代码依赖。
6. 通用资源服务、类型加载器、CPU数据、设备对象、世界实例的边界和清理责任；加载完成不是统一的布尔含义。
7. 用一份角色外观资产说明离线加工、请求/依赖、专业创建/上传、框架实例化及延迟释放；数据流另图。
8. 业内相近原则与不同划分：Godot、UE、O3DE官方材料；不推广成所有引擎共同的模块表。
9. 反例与审查问题：资源管理器调用场景、平台认识角色、全局上下文掩盖依赖、按层推断线程；按规模裁剪。
