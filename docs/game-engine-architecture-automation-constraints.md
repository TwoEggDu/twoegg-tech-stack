## 增量与正文

- 按明确授权范围完成可审核增量；单篇新写默认只解决一个主问题，系列修订可按工作单同时维护多篇。
- 先解释公共问题与模型，再使用已核对的具体引擎资料；例子写清输入、状态、输出、完成与清理。
- 保持职责分类、代码依赖、运行调用、数据交接、线程时序各自的含义；图先标箭头语义。
- 不用产品名称或文档目录证明架构优劣、统一层数、线程或性能。删除重复内部状态说明，保留必要的版本和证据边界。
- 正文保留现有栏目与URL；规划、证据和验证记录放在docs。不要创建占位正文或重复课程。

## 证据与验证

- 在公开仓使用可公开引用的证据，遵守Unity C++源码隔离规则；不能为了源码优先复制受限材料。
- 每个关键事实注明来源与版本；具体调用、运行、线程与性能结论需要各自证据。缺少运行记录时保留为待验证，不把文档核对写成实测。
- 一般原理文章可以依据公开资料完成，不因私有源码路径缺失而自动阻塞。只有确实依赖缺失证据的结论需要收窄或等待。
- 回写canonical状态和相关导航；执行记录保存构建、链接、元数据和图表的实际检查结果。
