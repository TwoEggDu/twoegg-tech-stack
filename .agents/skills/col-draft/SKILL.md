# 初稿骨架生成

把已有准备材料组织成可展开的写作骨架，不把未核实的论点、案例或实验填成成稿事实。用户要求完整正文时，按 twoegg-article-method 继续写作，不把本技能的骨架产出当作整项任务已完成。

## 定位与材料读取

- 接受文件路径、现有提纲、工作单、深挖稿、验证设计、审查记录或当前对话内容；不要求材料必须由某个技能在本聊天生成。
- 先读取用户给定材料。需要系列范围时从[根路由](../../../doc-plan.md)进入 canonical plan，再读 `content/` 中本篇和必要的前置。`docs/` 的 outline、workorders、证据卡是准备材料，`examples/` 的记录按需引用，`kb/` 是知识沉淀。
- 篇级边界以 canonical plan 为准；执行材料不能静默覆盖系列目录。用户明确的新要求与旧计划不同时，说明差异，并在当前授权范围内组织骨架，不自动回写规划。
- 根据材料和系列判断读者与文章类型，不预设 Unity 背景。需要定位调整时参考[站点定位](../../../docs/site-entry-and-audience-plan.md)，写法以[文章方法](../../../docs/article-writing-method.md)和[对应模板](../../../docs/article-outline-template.md)为准。

## 材料足够与缺失时

- 主题、核心问题、边界与主要论点已有依据时，可以直接生成骨架，不强制先运行 col-editor、col-drilldown 或整条技能链。
- 只有部分材料时，用已有内容搭出有限骨架，标清哪些是材料支持、编辑组织建议或待补证据；论点可来自正文、outline、工作单或研究稿，不限七层分析稿。
- 缺少主题或关键边界且无法可靠判断时，先询问缺少的关键项；不要把未读仓库文件误判为材料不存在。
- 案例真实经历、因果根因、实验结果与数字需要来源。缺少真实数据或经验时使用仓库的 `DATA-TODO` / `EXPERIENCE-TODO` 注释；未执行实验只写拟验证。

## 骨架内容

1. **文章信息**：拟标题、类型、系列位置、读者、前置知识、核心问题、本轮使用的材料与证据缺口。
2. **开头任务**：用什么问题、现象或对照带入；写方向，不代写开头段。
3. **H2 骨架**：优先沿用有效的现有 outline，按文章类型调整，说明每节职责、核心论点、材料来源及待补内容。
4. **必要辅助内容**：术语首次定位、例子、代码、图表或验证块放在哪里，仅在有用时列出。
5. **边界与结尾任务**：哪里收束核心问题，哪些内容留给其他篇，必要的阅读去向与写作风险。

不要求每节对应某个七层编号，不把所有类型都改成“原理→实现”。不强迫每节重复“不涉及某某，见某篇”；边界说明集中放在合适位置，导航遵循[呈现约定](../../../docs/article-presentation.md)。

## 输出示例

某现有提纲已列出“固定审查对象”一节：

- **本节职责**：说明批准与检查对应哪份候选。
- **核心论点与来源**：沿用提纲中基线、候选修订、差异与依赖的列表。
- **待补证据**：平台版本、批准后修改及最终合入记录；不能写成已经测试过的能力。

骨架是作者工作材料，不是读者正文；不输出整篇润色后的文章，也不把缺失的深挖稿当成必须停工的理由。
