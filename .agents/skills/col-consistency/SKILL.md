# 系列一致性审查

比较本篇与系列约定、相关正文的口径，不把合理的主题、版本或文章类型差异当作错误，不改文风。

## 定位与材料读取

- 接受文章文本、路径、工作单、既有审查记录与当前对话材料。已有路径就直接读取；不能确定本篇或所属系列时先利用文件元数据与[根路由](../../../doc-plan.md)定位，仍不明确才询问。
- 沿根路由读本系列唯一 canonical plan，再读 `content/` 中本篇及有直接依赖、重叠或引用关系的文章。先局部，发现跨系列冲突再扩展，并列出实际覆盖范围。
- `docs/` 的执行计划、outline、证据卡用于补充状态和依据，不能当已发布正文或覆盖系列目录；`kb/` 是知识沉淀。历史归档只供追溯，不更新，不默认全站扫描。
- 目标、读者与基线来自系列和本篇；跨系列定位按需读[站点定位](../../../docs/site-entry-and-audience-plan.md)。不存在全站统一的 Unity / URP / 工具版本前提。没有找到系列规划时，说明本轮只能检查本文及已读材料。

## 五类检查

| 类型 | 判定方式 |
|---|---|
| 术语 | 同一对象是否发生无说明的改名或语义漂移；有意区分的对象不强行合并 |
| 基线与证据 | 核对相关工具、框架、系统、平台、配置和实验范围；只有前提相同却结论冲突，或未交代差异时才判问题 |
| 职责与层级 | 与系列分工和[文章类型](../../../docs/article-writing-method.md)是否匹配；原理、实现、项目示例同段出现不自动等于混写，以是否造成因果或对象混淆为准 |
| 导航 | 前置和扩展链接是否必要、目标真实、描述准确；按[呈现约定](../../../docs/article-presentation.md)考虑模板已生成的系列导航，不要求再手写重复返回或前后篇链接 |
| 重复与口径 | 完整重复了前文哪些内容、是否改变结论；为独立阅读而保留的简短定义不一律删除 |

基线检查还要区分：官方资料、静态源码、实验观察、工程建议与未验证假设。正文存在、构建通过或计划标记不能替代运行验证；不同证据范围不等于结论必然冲突。

## 输出

1. **审查范围**：本篇、canonical plan、实际读取的相关正文、未覆盖项。
2. **具体问题**：引用本篇路径、行号与原句，同时给冲突来源和最小处理建议；每条标注术语漂移、条件缺失、职责重叠、缺必要链接、重复解释等实际类型。
3. **必要补链 / 去重 / 术语统一**：只输出存在问题的项目，可用表格；标明已有正文、提纲或计划目标。引用不存在的计划页时标待建立，不编造可点击目标。
4. **待确认项**：证据不足的冲突单列，不能作为已确认修改项直接交给改写。

无问题就报告“本轮已读范围内未发现与系列约定冲突的内容”，不填空表、不承诺整个系列已通过发布验收。合理差异可以简要解释，不扩展成文风建议。

## 示例

两篇分别使用不同 Git 版本做教学实验，只要明确版本、场景与结果范围，就不应强制改成同一版本；如果把一篇的局部实验写成另一篇所有环境下的保证，才应指出条件缺失与证据外推。
