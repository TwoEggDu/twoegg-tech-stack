# 版本与证据风险审稿

只定位有风险的表述，给出依据与最小修正建议；不润色全文，不代替发布验收。

## 材料读取

- 接受文章文本、文件路径、仓库审查记录或当前对话材料。先读用户指定的内容；没有文本参数不等于没有输入。确实无法定位文章时才询问。
- 需要系列背景时，从[根路由](../../../doc-plan.md)读取相关 canonical plan，再读对应 `content/` 文章。`docs/` 中的 outline、实验设计与证据卡是支持材料，不当作已发布正文；`kb/` 是知识沉淀。
- 局部审查只覆盖指定片段；定位、经验与证据身份以[站点定位](../../../docs/site-entry-and-audience-plan.md)及本系列约定为准，不把所有主题限定为 Unity / URP。
- 涉及具体机制、版本、平台或变化信息时核对适用的官方资料、公开源码或原始记录。无法访问或用户限定仅用现有材料时，明确标“待核查”，不假装已完成事实核验。

## 风险类型

| 类型 | 检查内容 |
|---|---|
| 绝对化 | “一定、永远、零代价”等是否有足够依据和成立条件 |
| 版本 / 环境依赖 | 引擎、库、工具、系统、平台、配置与目标环境是否被遗漏或外推 |
| 无据经验与数字 | 性能、收益、故障、个人贡献、玩家指标是否有可核对来源与测量口径 |
| 证据越界 | 将规范、静态源码、教学实验、工程建议或假设写成其他证据类型；把局部测试写成生产保证 |
| 状态越界 | 将提纲、实验设计、构建通过、提交、部署或线上效果混为同一完成状态 |
| 公开边界 | 受限源码、内部资产、凭据、可识别内部信息是否适合公开；遵守仓库双仓与脱敏约定 |

## 输出

先说明审阅范围、已读材料、核验方式与未覆盖项，再报告发现数量。只列有具体依据的问题：

| 位置与原句 | 风险类型 | 问题与已有依据 | 最小修改建议 | 待核查材料 |
|---|---|---|---|---|

- 文件输入给路径与行号；文本输入引用完整相关句。问题应具体到原句与条件，不能只写“第三段有风险”。
- 有证据支持修正时，给可直接替换的句子并标来源；缺少证据时写“暂不能给出可直接替换句”，列出所缺材料和处理方向。
- 查证后的事实修正与仅调整措辞分开说明；不通过加“通常”“可能”掩盖无依据的事实。
- 无问题时写：“本轮在所列范围内未发现上述类型的高风险表述。”保留核验限制，不给“可直接发布”的结论。[发布检查](../../../docs/article-presentation.md)另行执行。

## 修正边界与示例

不能自行补版本号、平台、测试条件或实测数字；待填占位符不是已核实事实，也不能当作可直接发布的替换句。不改变原意来制造表面稳妥。

例如原句“我们实测加载快了 30%”，但没有原始记录：应要求测试环境、基线、指标和记录，不能改成“在 Unity 2022.3 下通常快 30%”，也不能把未执行的实验写成已测。
