# 工程验证设计 — 最小可验证案例

把待验证结论转换为可证伪的实验设计，说明变量、指标、对照与判定依据。本技能只输出设计；用户另行要求执行时，按授权范围执行并单独记录实际结果。

## 定位与材料读取

- 接受主题、结论、文件路径、工作单、现有实验设计或当前对话材料。先读已给内容，不要求粘贴已有文件。
- 需要系列范围时，从[根路由](../../../doc-plan.md)进入 canonical plan，再读 `content/` 相关文章。`docs/` 保存 outline、执行计划和证据卡；优先复用 `examples/` 的相关实验与原始记录，`kb/` 按需参考，不默认扫描全站或归档。
- 环境与工具由待验证命题决定，支持引擎、Git、构建、服务端和协作流程，不统一要求 Unity 版本或渲染工具。
- 具体版本、API、面板路径和行为有疑问时核对官方资料或现有工程；没有依据的路径、阈值和能力标“待核查”。已有材料写明版本时沿用实际范围，不虚构已安装环境。

## 每个验证块

默认最多 3 个，优先验证核心结论；按用户范围调整，不凑数量。

1. **命题与证据缺口**：一句可证伪的结论；说明已有规范、静态核对、历史实验及还缺什么。本轮若只设计，不写成已实测。
2. **环境与最小输入**：相关工具、引擎、系统或服务版本、配置、数据集和所需对象；不适用的字段省略，未确定的环境明确待定。
3. **隔离范围与前置状态**：实验目录或环境、测试数据、初始状态和必要权限。默认使用独立临时目录、自建测试资产及测试服务，不把实验设计当作操作生产环境的授权。
4. **变量与对照**：自变量、固定项、排除项，以及能证明观测确实区分命题真假的负对照或失败场景；说明重复测量是否必要及原因。
5. **步骤与观测工具**：可实际搭建的顺序、数据采集点、工具与命令或面板；按命题选择日志、散列、版本身份、Profiler、测试回执等，而不是只说“运行看看”。
6. **指标与判定标准**：指标定义、单位、采样方法及通过 / 失败 / 无法判定条件。性能比较说明基线和统计口径；没有依据的数值标为待校准，不预填收益。
7. **预期与异常排查**：明确这是待验证的预测；对可能不符的现象给可检查原因，避免把预测写成结果。
8. **证据产物与结束状态**：原始输出、版本身份、日志或截图保存位置，以及测试服务停止或临时资源清理安排；如拟删除资源，执行时仍需核实实际目标。
9. **结果边界**：列出该实验能回答什么、不能外推什么。设计完成、脚本返回成功、静态一致、引擎运行和线上效果分别记录。

## 输出与示例

开头说明已有参考、本次复用与补充范围；随后给验证块，最后列实际开做前缺少的环境或材料。设计可以在环境待定时继续，但不得宣称已经满足运行前置或已经通过。

例如 Git 提交范围实验：在临时仓库构造任务 A 与无关修改 B，观察候选 tree、接收方取得的提交身份及开发目录 B 的字节和删除状态；加一个漏依赖的失败对照。这样的检查不能代替 Unity 资源依赖、编辑器缓冲区或覆盖后恢复验证。
