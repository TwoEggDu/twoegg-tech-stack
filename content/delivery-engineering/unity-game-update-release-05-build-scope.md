> 贯穿案例：先打客户端 100 完整包，再分别构建 Res、HotCode、Data 和全部热更内容。

## 1. 一次构建先固定哪些输入

- 固定平台、环境、源码、资源输入、SDK Profile 和客户端基线。
- 区分开发构建与正式构建，说明同为 WebGL 不代表平台身份相同。

## 2. 用五个选项表达构建范围

- 使用 Full、HotUpdate、Res、HotCode、Data，并给出内容矩阵。
- 说明这些是本系列约定，不是 YooAsset 内置枚举；原项目名称只作源码对照。

## 3. 版本如何递增与继承

- Full 建立新客户端及完整内容快照；独立内容构建沿目标客户端更新对应版本。
- 未构建内容继承既有版本，记录实际分配结果，不假设每个计数器都在本地加一。

## 4. 资源更新到底给哪个客户端

- 显式核对目标整包策略，区分最新已注册包与当前生效策略。
- 没有可用基线时拒绝隐式拼接不完整资源组合。

## 5. 热更构建为什么依赖客户端基线

- 说明热更程序集、AOT 元数据、平台和 Profile 的对应关系。
- 解释改变底层能力时为何需要重新构建客户端，不能仅替换 DLL。

## 6. 怎样核对构建结果

- 对照产物目录、版本映射、清单、源码身份和构建回执。
- 构建成功只表示该步骤产出成功；上传、生效与设备验收分别交给后续步骤。

## 本次构建内容对照

| 构建选项 | 中文名称 | 客户端程序 | 游戏资源 | 热更代码 | 游戏数据 |
|---|---|:---:|:---:|:---:|:---:|
| `Full` | 完整客户端 | ✓ | ✓ | ✓ | ✓ |
| `HotUpdate` | 全部热更内容 | — | ✓ | ✓ | ✓ |
| `Res` | 游戏资源 | — | ✓ | — | — |
| `HotCode` | 热更代码 | — | — | ✓ | — |
| `Data` | 游戏数据 | — | — | — | ✓ |

`Res` 指模型、动画、特效、UI、场景和音频等游戏资源；`HotCode` 仅指可热更新的代码；`Data` 指配置、关卡和模板等运行数据。

这五个名称是本系列的构建约定，不是 YooAsset 内置枚举。`HotUpdate` 表示构建三类热更内容，上传与上线仍是后续决定。
