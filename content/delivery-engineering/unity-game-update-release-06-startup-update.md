> 贯穿案例：客户端 100 从 R16 更新到 R17；分别检查首次启动、有旧缓存、Data 下载中断，以及必须安装 101 的玩家。版本与兼容条件沿用[第 04 篇]({{< relref "delivery-engineering/unity-game-update-release-04-version-binding.md#version-contract" >}})。

## 1. 先选定本次启动采用的策略与组合

- 首包启动器读取 BuildInfo，取得并检查业务版本清单，按平台、渠道、环境、客户端与稳定人群归属选定策略。
- 记录 `policyRevision` 和 `releaseId`，检查基线及兼容声明；选中 R17 后，各 Package 都取 R17 的明确版本。
- 远端策略在准备期间变化时，不逐包混入新内容。若准入要求发生变化，停止本次采用，在安全边界重新选择并检查完整组合。

## 2. 什么时候需要客户端强更

- 按第 04 篇的支持下限与逐客户端升级规则决定是否拦截业务，再核对渠道可取得且满足要求的目标客户端。
- 区分“100 必须安装 101”与“100 必须采用 R17 内容补丁”；后者仍可保留客户端程序不变。
- 画出目标不可得、用户取消、下载或应用失败的分支；不进入尚不满足准入条件的游戏，也不把提示退出记录为更新成功。

| 分发形态 | 正文需要核对的整包更新链路 |
|---|---|
| Android 的具体渠道 | 按渠道能力选择商店跳转、受支持的应用内更新或安装流程，核对下载、安装与重新启动结果 |
| 浏览器 WebGL | 核对页面、启动脚本与构建内容的发布和缓存刷新，重新进入时确认实际客户端身份 |
| 具体小游戏平台 | 分别核对平台新包可取得、下载、应用或重启的 API 与回调；微信和抖音不合并成同一实现 |

## 3. 准备哪些内容由产品策略决定

- 按选定组合加载所有必要 Package Manifest，核对文件身份，再计算本次准备集合与已有缓存的差异。
- 比较启动前准备全部内容、只准备启动必需内容、预下载后续关卡三种选择；结合包体、弱网、存储及宿主能力作决定。
- Android 也可以按需下载；WebGL 的准备范围同样需设计。本案例的下载选择不写成平台固有规则。
- 下载器零待下载仅说明当前集合没有缺口；若 Res 后续按需取得，也必须继续解析同一组合，不能另取 latest。

## 4. 从已选择到实际采用有哪些状态 {#adoption-states}

| 状态 | 必须满足什么 | 在此中断后怎样处理 |
|---|---|---|
| 已选择 | 策略有效，选中完整且兼容的组合 | 重启后重新检查准入与选择，不仅凭本地版本号继续 |
| 准备中 | 按固定组合下载，记录文件身份和进度 | 已校验文件可复用；未完整文件按下载器支持方式继续或重试 |
| 已准备 | 所需清单与启动必需文件校验通过，依赖与基线检查通过，完成记录可持久化 | 记录和文件不一致时重新检查；尚不能宣称业务启动成功 |
| 本次进程采用 | 加载对应 AOT 元数据、HotCode 与 Data，并进入启动流程 | 一旦进入代码加载阶段，按可能已有副作用处理，不在当前进程混入旧 DLL |
| 启动检查通过 | 完成规定的业务启动检查，记录实际客户端与组合 | 保存最近成功记录；该记录是否允许恢复仍受当前策略与服务端约束 |

- 说明准备完成记录的提交顺序与中断一致性：先验证，再提交完成记录；部分文件就位不能提前宣布整个组合可用。
- 跨 Package 一致采用是项目协调逻辑，不能由单个 Package 下载成功推出；按需 Res 的未来下载失败仍需要业务恢复路径。
- 本系列采用普通 HybridCLR 程序集加载流程。程序集加载后的恢复按重启设计；特定热重载能力另有版本与业务约束，不在本案例中默认具备。

## 5. 走通 Data 21 下载一半被关闭的案例

1. 客户端 100 已选 R17，HotCode 8 文件校验通过，Data 21 还未完成；当前组合不能标为已准备。
2. 再次启动先检查当前策略。仍允许 R17 时，复用身份吻合的文件并补齐 Data 21；不能拿 Data 20 凑成 R17。
3. 如果策略改选 R16，则整体按 R16 重新准备和采用。磁盘保留 HotCode 8 的缓存不等于进程已经采用它。
4. 若此前已经加载 HotCode 8 后才失败，结束该次业务启动；在新进程重新选定并检查组合，不声称切回清单即可撤销加载。

## 6. 哪些失败可以恢复，哪些必须停止

- 覆盖清单请求失败、策略缺失、文件不存在或损坏、空间不足、用户取消和程序集加载失败，分别记录失败阶段。
- 历史成功组合只有仍被允许且与当前服务端相容时才可恢复；禁止绕过强更下限或必须内容补丁。无有效策略时按明确的离线/缓存有效期规则处理。
- 新安装无历史成功组合时，解释内置基线能否启动；避免无限重试、反复崩溃或无条件“回到最新”。
- 输出启动回执：客户端与基线、`policyRevision`、`releaseId`、准备范围、实际内容版本、采用阶段及失败原因，供第 07 篇观察与决策。
