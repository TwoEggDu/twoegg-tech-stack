研究者已经能抬起手臂，也能握住法杖。现在要让玩家一眼看出他在准备施法、力量何时释放，以及受到攻击后为什么停下。

这需要决定姿势、运动路径与时间节奏。进入游戏之后，还要面对另一类问题：玩家可能在收势时继续移动，也可能在起手时受击；动画不能只按制作软件里的时间轴从头播到尾。

**动画制作把意图组织成随时间变化的姿势，运行系统再根据游戏状态选择、组合和切换这些动作。** 两边需要共同约定动作的时点、位移与取消方式。本篇从动作怎样做开始，走到 Unity 中怎样播放和被打断。

> **读这篇之前**：先看[第 04 篇绑定与蒙皮]({{< relref "delivery-engineering/game-art-production-04-rigging-skinning.md" >}})，分清制作控制器、变形骨架与蒙皮。这里复用其简化手臂；客户端完整接入与生命周期归 10，特效制作归 08。

> **版本与证据范围**：操作方案参考 Maya 2024、3ds Max 2024 与 Unity 6（6000.0）官方资料。帧数、角度、目录、过渡参数和示意图是本文的教学选择。尚未实际制作 DCC 动作原稿、FBX 或 Unity 工程，也没有执行播放、混合和打断实验；下文提供待实操的步骤及观察条件，不把预期写成实测结果。

## 先决定角色在表达什么，再决定打哪些关键帧

同样是抬手，招呼、举盾和施法可以有相近的关节角度，却表达不同的意图。差异来自身体如何准备、动作朝哪里发力、哪些部分先动，以及在哪一刻停顿或加速。

### 从关键姿势建立可读性

先把施法拆成几张值得被看清的姿势：准备、蓄势、释放、余势和回到可行动状态。此时先看轮廓、重心与法杖指向，不急着让所有部位都连续运动。

对于完整角色，可以从游戏摄像机下检查：法杖是否被躯干挡住，蓄势与释放能否区分，身体是否朝目标组织发力，双脚能否支撑这个姿势。把视角切成漂亮的近景，不能代替实际游戏视角下的可读性。

接下来安排节奏。蓄势稍留一点时间，释放更集中，身体与衣物随后跟上，会形成不同于匀速抬手的感觉。这些是围绕本例目标的制作判断；不同角色的重量感、技能强度与操作反馈，需要重新取舍。

### 从动作草稿走到曲线与细化

可以先做 **blocking（关键姿势草稿）**：只确定重要姿势出现在哪些帧，用阶梯式切换检查构图与节奏。确认后再加入过渡姿势，调整手、肘、肩、躯干的先后关系，最后处理轨迹、手指、持杖接触和细小的停顿。

曲线编辑发生在这个过程中。关键帧记录某时刻某个通道的值，曲线描述这些值在时间上的变化；切线影响进入和离开关键帧的方式。曲线更平滑，并不自动意味着动作更有力。释放段被拉得太缓，也可能把原本需要的瞬间感磨掉。

对完整角色还要沿法杖尖端或手腕看运动轨迹。某个旋转通道看起来很平整，几个关节叠加后，末端仍可能绕出不合理的折线。判断最终姿势与轨迹，再回到相应控制器修正。

动捕是另一种动作输入：它能提供表演数据，之后仍要做清理、重定向、接触修正和游戏节奏调整。本篇以手工关键帧为主，不假设获得一段动捕就完成了游戏动作。

## 分清制作曲线、动作片段与运行状态

在制作软件里，动画师可能操作几十个控制器。导出时，需要把控制系统求出的结果写成目标骨架可使用的变换曲线。进入游戏后，这些曲线被导入为动作片段，再由运行系统决定什么时候使用。

这里有三个不同层次：

- **制作曲线**：例如肘部控制器的旋转曲线，方便调整姿势和节奏；约束与 IK 还会参与求值。
- **动作片段（Animation Clip）**：一段有起止范围的数据，例如待机或施法；播放到某时刻可以得到相应姿势。
- **运行状态与组合**：决定正在待机、进入施法还是受击，以及两个片段如何过渡、哪些身体部位参与混合。

制作端的帧间插值、运行时两个状态之间的过渡、Blend Tree 按参数混合，是不同的问题。它们都可能改变中间姿势，但不能用同一个“平滑一点”替代具体判断。

## 用三段手臂动作建立一个小练习

继续使用上一章的局部手臂：`root → shoulder_r → elbow_r → wrist_r → hand_end_r`，网格与骨架保留在原有 `asset_export` 输出层级下。本篇只做肘部弯曲，根节点保持不动。

Maya 与 Max 是两条可选制作路径，各自从对应的绑定原稿出发；不要求把一套动作来回转过两种软件。沿用原有单位与坐标，先确认弯曲方向，再开始打帧。

本例选择 **24 fps**，在一个动作原稿中安排三个独立范围：

| 片段 | 源帧范围 | 本例关键帧与肘部弯曲量 | 用途 |
| --- | --- | --- | --- |
| `Idle` | 1—25 | 1：0°；13：2°；25：0° | 小幅循环，观察首尾衔接 |
| `Cast` | 49—73 | 49：0°；55：20°；61：65°；67：60°；73：0° | 区分准备、释放与回落 |
| `Hit` | 97—109 | 97：0°；100：35°；109：0° | 较快进入另一段姿势，检查打断 |

</div>

这里的角度是相对本例起始姿势增加的弯曲量，**不是要求两个软件都填写相同的 Rotate Z 数值**。关节定向、控制器零点和骨骼局部轴会影响实际通道；先用一个小角度确认弯曲轴及正负方向，再将对应值映射到表中。

1 到 25 之间有 24 个帧间隔，在 24 fps 下名义时长为 1 秒；49 到 73 同样为 1 秒，97 到 109 为 0.5 秒。记录帧率与起止范围，避免把“25 个编号”直接当作 25 个时间间隔。引擎导入后还要核对实际片段时长。

每段的起点和终点都显式设置所需通道；肩、腕和根节点在本例保持既定基准。不要让后一段起点依赖前一段残留的姿势，也不要把 26—48、74—96 的空隙导入有效动作。

**这个练习只能帮助检查数据传递和切换。** 一根手臂没有重心转移、脚步和躯干发力；上述小幅待机不是完整呼吸表演，`Cast` 和 `Hit` 也只是片段用途的代号。全身角色仍须按前面的动作目标重新制作。

## 在 Maya 中制作：打关键帧、调节奏，再修曲线

### 准备动作原稿与控制对象

从上一章的 `arm_rig_maya_v001.ma` 另存为 `arm_anim_maya_v001.ma`，保留绑定原稿。正式项目也可以引用绑定文件，让动作文件保存动画；本例先用独立副本，降低第一次操作的依赖复杂度，并记录它使用的是哪一版绑定。若文件里保留了上一章的短测试动作，先在动作副本中清理其动画关键帧，再制作本篇三段；保留绑定、约束与网格数据。

在 Preferences 的时间设置中选择 24 fps，将动画范围覆盖到 109；用 Time Slider 与 Range Slider 设置当前查看的片段范围。先关掉 Auto Key，避免试摆姿势时无意写入动作。

如果上一章建立了肘部控制曲线与 Orient Constraint，就给控制器可动画的弯曲通道打帧，由约束驱动骨骼。若采用直接 FK 骨骼练习，则给对应关节的旋转通道打帧。两条路径选一条，不要同时给受约束骨骼和控制器输入互相冲突的旋转。

### 按表建立三段动作

先做 `Cast`，再用相同方法做另外两段：

1. 将当前时间移到第 49 帧，让手臂回到已记录的起始姿势。
2. 在 Channel Box 中选择要记录的旋转属性，填写值并确认，再用右键菜单 **Key Selected** 打关键帧。固定通道也在片段边界写入明确的基准。
3. 移到 55、61、67、73 帧，分别摆出表中的弯曲量，每次修改后明确打帧。
4. 将播放范围缩到 49—73，先看姿势顺序与节奏。起手、释放、回落是否能区分，是否存在意外跳变？
5. 回到 1—25 和 97—109，分别制作 `Idle` 与 `Hit`。逐段播放，避免通过整条时间轴的空隙误判动作时长。

Channel Box 的按属性打帧方式可参考 Autodesk 的[设置关键帧说明（2023）](https://help.autodesk.com/cloudhelp/2023/ENU/Maya-Animation/files/GUID-154C65AF-D65E-4356-A49B-E9B5BF05754A.htm)；这里保留该帮助页的版本，实际菜单以安装的 Maya 2024 为准。本文不依赖快捷键布局。

### 用 Dope Sheet 改时间，用 Graph Editor 改运动变化

打开 **Windows → Animation Editors → Dope Sheet**，先整体移动相关关键帧，检查释放来得是否过早、回落是否占用太久。完整角色的一个关键姿势涉及多个控制器时，要一起移动对应关键帧，避免手已经释放而身体还在蓄势。

再打开 **Graph Editor**。草稿阶段可给选中的关键帧使用 Stepped 切线，只看重要姿势；细化阶段再改为合适的连续切线，检查缓入缓出、停顿和过冲。对本例尤其要看 61 帧附近是否超过原定弯曲范围，25 帧回到 1 帧时速度是否突然改变。

首尾姿势相同只解决了位置衔接，循环还需要看进入与离开边界的速度。肘部看起来在同一个角度，也可能因为两端切线不同而每轮“顿一下”。完整步行动作还须一起检查脚接触、重心及左右脚相位。

Maya 的 [Graph Editor 说明（2024）](https://help.autodesk.com/cloudhelp/2024/ENU/Maya-Animation/files/GUID-9E69ABB3-E94B-4D67-9935-40F77FD2E9E0.htm)解释了关键帧与切线，也提醒 IK 或表达式不一定直接表现为可编辑曲线。控制器曲线与最终骨骼结果要分别检查；只看控制器通道，不能证明导出骨架已经获得了同样的运动。

完成后保存动作原稿。Playblast 可以帮助回看表演与节奏，但它是评审视频，不能代替包含骨骼曲线的动作交付物。

## 在 3ds Max 中制作：明确记录关键帧，再调整曲线

### 从绑定文件建立动作文件

打开上一章的 `arm_rig_max_v001.max`，另存为 `arm_anim_max_v001.max`。保留 Bones、Skin、根辅助对象及输出层级，不改变骨骼长度、父子关系和绑定基准。在动作副本中清理上一章短测试动作的动画关键帧，保留 Skin、控制器结构与绑定数据，再开始本篇练习。

在 **Time Configuration** 中选择 Film（24 fps），把动画范围扩展至 109，并记录设置。帧率应在制作前确定；制作完成后更改时间设置，需要重新检查关键帧时间与动作秒数，不能只改标签。

直接 FK 练习选中承担肘部弯曲的骨骼；若已有控制对象，则给相应控制器打帧。先确认局部旋转轴、零点与正方向，再把教学角度换成对应的实际旋转值。

### 用 Set Key 建立可控的动作草稿

本例采用显式 **Set Key**，便于知道哪些修改被记录：

1. 选择需要动画的骨骼或控制器，开启 **Set Key Mode**。
2. 在 **Key Filters** 中保留本例需要记录的 Rotation；如果还有明确需要的位移或其他通道，再加入对应类型。
3. 把 Time Slider 移到 49，摆好基准姿势，点击 **Set Keys** 按钮记录。
4. 移到 55、61、67、73，修改旋转，并在每一处点击 Set Keys。
5. 用同样的方法做 1—25 的待机及 97—109 的受击，逐段缩小播放范围检查。

**开启 Set Key Mode 后，摆姿势并不等于已经写入关键帧。** Autodesk 的 [Set Key 说明（2024）](https://help.autodesk.com/cloudhelp/2024/ENU/3DSMax-Animation/files/GUID-99745DB9-C1A9-47B2-8481-91975FC3A399.htm)区分了修改姿势与提交关键帧；未点击记录就移动时间，修改可能丢失。Auto Key 则会在开启时记录相应动画修改，使用时同样要控制对象和通道范围。

### 在 Track View 中调整时间和切线

使用 Track View 的 **Dope Sheet** 调整关键帧时间，使用 **Curve Editor** 查看旋转随时间的变化。草稿先确认关键姿势，随后选择关键帧、调整切线与过渡，检查释放附近的速度变化和边界衔接。

Max 的控制器类型会影响可编辑曲线和插值方式。这里使用基础 FK 旋转练习；如果项目使用 Biped、CAT、约束或自定义控制系统，先在原控制体系中完成制作，再检查输出骨骼的求值结果，不把某种曲线操作当作所有绑定的通用入口。

两套软件最终应比较的是：对应时刻的姿势、运动方向、节奏和输出层级。它们的局部欧拉角数字可以不同，不必为了让数值相同而破坏各自绑定。

## 从动作原稿到 FBX：输出骨架结果与正确的时间范围

### 为什么要烘焙，为什么不能丢掉原稿

制作控制器可以通过约束、IK 或软件特有控制系统驱动骨骼。目标引擎不一定支持同样的求解方式，因此需要把指定时间范围内求出的骨骼变换采样为动画曲线，这就是本例烘焙的目的。

烘焙后仍要检查：每个输出骨骼是否有需要的通道，是否保留父子层级，开始与结束是否正确，采样后运动是否接近原结果。它不能自动修复错轴、漏选骨骼或不合理动作。

可编辑控制系统保存在 `.ma` 或 `.max` 原稿中。不要为了得到可导出曲线，覆盖掉唯一的制作文件；后续要改施法节奏时，仍然需要回到有控制器和关键姿势的版本。

### 先固定输出层级，再导出包含三段动作的文件

本例先将 1—109 帧作为一个完整时间范围，导出一份 `arm_actions.fbx`，在 Unity 中再划分三个有效片段。第一次验证时，文件包含与上一章相同的必要网格、Skin 和完整输出骨架，方便比较；场景仍只使用基础模型的一份实例。

**一个 FBX 文件不等于一个动作片段。** 本例选择先完整输出再分段，是为了让烘焙与片段边界各有明确检查位置；不能仅凭 Bake Animation 的 Start / End，就假定文件中所有已有曲线都被裁成独立动作。

后续可以改为每动作一份文件，或“模型一份、动作文件只保留所需骨架和曲线”，但要重新核对有效时间范围、动画路径、根节点及 Avatar 兼容性。不要通过随意删掉祖先节点来追求文件更小，否则相同名字的骨骼也可能出现在不同路径下。

**Maya 路径：** 选择约定的 `asset_export` 输出内容，使用 **File → Export Selection → FBX**。开启 Animation，展开 **Bake Animation**，填写 Start=1、End=109，Step=1；本例为了先比较固定采样结果，同时启用 **Resample All**。带蒙皮网格时，保留 Deformed Models 下的 Skins。输出 `arm_actions.fbx`，导出前检查范围覆盖了全部三个片段。

Maya 的 [FBX 导出选项（2024）](https://help.autodesk.com/cloudhelp/2024/ENU/Maya-Basics/files/GUID-FE8DBEAA-C2DD-43B3-9933-4BA4CDDEAA89.htm)区分了动画烘焙、重采样和变形数据。控制器不作为运行骨架交付时，也应保持其在源场景中可正常求值，并检查 FBX 中的骨骼结果；不能把“没有导出控制器”理解为“可以先删除控制器再导出”。

**3ds Max 路径：** 使用 **File → Export → Export Selected** 选择 FBX，输出相同用途的网格、根节点和骨架。开启 **Animation → Bake Animation**，填写 Start=1 / End=109 / Step=1，并启用 Resample All 作为本轮对照基线；在 Deformations 中开启 Skins。输出 `arm_actions.fbx`；时间轴空隙保留在交换文件中，之后从有效 Clip 范围排除。

Max 的 [FBX Animation 说明（2024）](https://help.autodesk.com/cloudhelp/2024/ENU/3DSMax-Interoperability/files/GUID-31EA2A4F-A126-498B-96E8-31811522738A.htm)指出 Bake Animation 可将不支持的约束和控制器结果转为曲线；Resample All 会连同已支持的动画一起重采样。它还特别说明 Start / End / Step 不保存在预设中，所以每次重新导出时必须重查。

Step=1 在本例表示按源场景的 24 fps 逐帧采样；它不要求游戏固定以 24 fps 渲染。进入引擎后，片段仍会按播放时间求值。减少采样、曲线压缩及误差阈值可以后续比较，先别同时改变所有变量。

## 进入 Unity：先导入片段，再让一个角色播放

### 导入设置与骨架兼容

将动作 FBX 放入 `Assets/Art/Researcher/AnimationTest/Animations/`。先选择 Maya 或 Max 的一套来源，使用与其匹配的上一章 `arm_rig.fbx`；比较另一套时使用独立测试目录和对应模型，避免同名文件覆盖。

基础模型保持 **Generic → Create From This Model**，根节点沿用上一章的 `root`。动作文件在 Rig 中选择 **Generic → Copy From Other Avatar**，Source 指向对应基础模型的 Avatar，然后 Apply。

这建立在相同骨架结构和输出约定上。Unity 的 [Generic 导入说明](https://docs.unity3d.com/6000.0/Documentation/Manual/GenericAnimations.html)允许模型与各动画文件复用同一 Avatar，但要求相同骨架结构。Copy From Other Avatar 不会替你修复改过的父子层级、缩放或动画路径。

局部手臂继续使用 Generic，不强行配置 Humanoid。将完整人形通过 Humanoid 重定向到不同体型，是后续可以采用的另一种路径；仍需正确骨骼映射、姿态和接触检查，不能由本例证明“任意角色通用”。

打开 `arm_actions.fbx` 的 **Animation** 标签，开启 Import Animation。在 Clips 列表中用添加按钮建立三个条目，分别命名为 `Idle`、`Cast`、`Hit`，按表设置有效范围：1—25、49—73、97—109；将默认覆盖全时间轴的条目替换或删除，避免把空隙当作有效动作。Idle 开启 Loop Time，Cast / Hit 关闭；第一轮可将 Animation Compression 设为 Off，减少排查变量。

检查显示的帧范围与预览时长。导出文件可能保留源时间，也可能在特定输出设置下重新定位范围；按实际导入内容选择有效区间：先定位源第 1 帧对应的导入起点，再核对三个范围的位置、帧间隔和关键姿势，不能机械套用源帧号。分段流程见 [Unity 提取动作片段](https://docs.unity3d.com/6000.0/Documentation/Manual/Splittinganimations.html)，相应面板见 [Animation 导入属性](https://docs.unity3d.com/6000.0/Documentation/Manual/class-AnimationClip.html)。

先单独预览三个片段：角度、方向与时长是否符合源动作，释放姿势是否位于 Cast 中点，Idle 的边界是否停顿，根节点是否意外漂移。导入预览通过之后，再检查运行组合。

### 建立最小 Animator Controller

复制上一章的手臂测试 Prefab，命名为 `AnimationTest.prefab`。保留 Animator 所在层级与骨架相对路径，只将 Controller 改为新建的 `AnimationTest.controller`；Avatar 指向基础模型的 Generic Avatar，先关闭 Apply Root Motion。

在 Animator 窗口建立 `Idle`、`Cast`、`Hit` 三个状态，将三个片段分别放入其 Motion，设置 Idle 为默认状态；各状态 Speed 先保持 1。动作 FBX 中虽然也含网格，本轮场景只使用基础模型的一份实例，动作文件仅提供三个片段。

在 Parameters 中增加两个 **Trigger**：`Cast` 与 `Hit`。按下面的教学参数建立过渡，Transition Offset 均为 0；表中的时长启用 Fixed Duration，以秒解释：

<div role="region" aria-label="Unity 三状态过渡设置，可横向查看" tabindex="0" style="overflow-x:auto">

| 过渡 | 条件 | Has Exit Time | Exit Time | Transition Duration |
| --- | --- | --- | --- | --- |
| Idle → Cast | `Cast` Trigger | 关闭 | 不使用 | 0.08 秒 |
| Cast → Idle | 无参数条件 | 开启 | 0.95 | 0.12 秒 |
| Any State → Hit | `Hit` Trigger | 关闭 | 不使用 | 0.05 秒 |
| Hit → Idle | 无参数条件 | 开启 | 0.9 | 0.1 秒 |

</div>

Any State → Hit 关闭 **Can Transition To Self**，本例不希望受击状态因为再次请求同一状态而反复从头开始。各过渡的 Interruption Source 先设为 None，Ordered Interruption 保持开启；本例仅保留这一条 Any State 受击入口，后文解释它对过渡中断的特殊影响。

0.08 秒和 0.05 秒用于比较进入施法与受击的过渡，不是推荐给所有动作的固定数值。局部手臂即使切换顺畅，也不能证明完整角色的法杖轨迹或脚步没有问题。

### 在 Play 模式中先手动触发，再接游戏输入

进入 Play，选中场景中的手臂实例，让 Animator 窗口跟随这个运行对象。先看 Idle 循环，再点击 Parameters 中 Cast 的圆形 Trigger 按钮，观察状态进度与过渡；回到 Idle 后重复。

随后在 Cast 播放途中点击 Hit，检查是否转入受击并返回 Idle。这个步骤测试运行中的 Animator，区别于 FBX 面板里单片段的预览。不要在 Cast 或 Hit 忙碌期间连续点击 Cast 来模拟正常输入：本例还没有游戏侧输入许可与清理。

正式接入时，输入先交给玩法逻辑判断是否允许施法，再由表现驱动调用 `Animator.SetTrigger("Cast")`；受击成立且规则允许取消时，再请求 Hit。Trigger 被过渡消费后会复位，但没有满足过渡条件时可能仍处于待消费状态，取消动作时应清理失效请求，例如 `ResetTrigger("Cast")`。参数机制与脚本入口见 [Unity Animation Parameters](https://docs.unity3d.com/6000.0/Documentation/Manual/AnimationParameters.html)。

Animator 的状态组织负责表现。消耗法力、伤害结算、死亡优先级及网络裁决仍由相应玩法系统管理；不要把“当前动画看起来在待机”直接当成所有操作都合法的依据。

## 游戏中的混合：过渡、Blend Tree 和分层各解决什么

### 状态过渡改变姿势的交接方式

Idle → Cast 的过渡期间，旧动作与新动作会共同影响最终姿势，然后逐渐交给新动作。它能缓和姿势突变，但过长可能让施法起手显得迟缓，过短可能让手腕或法杖突然改变方向。

不要把 Transition Duration 当成“等这么久才开始播放 Cast”。目标状态会在过渡中播放，Transition Offset 决定从其时间线的哪里开始。判断释放姿势有没有被削弱，要一起看目标片段进度与混合权重。

先固定动作和速度，只比较几档过渡时长，再改源动作首帧、起手或收势；这样更容易判断问题来自哪里。完整角色还要看法杖与手的相对关系，以及切换后身体重心是否跳变。

### Blend Tree 用连续参数组合相关动作

有了完整角色的 Idle / Walk / Run 后，可以让移动速度控制 1D Blend Tree。一个小设置是：新建 `Locomotion` Blend Tree，Blend Type 选 1D，参数用 Float `Speed`，添加三个 Motion，关闭 Automate Thresholds，给出本文示例阈值 0、1.5、4，约定参数单位为米/秒。

运行侧将角色**实际运动速度**映射到这个参数，拖动参数预览待机、走、跑及中间组合。上述阈值只是假设素材的教学值，必须按照所用动作的步幅、周期及项目尺度校准；Blend Tree 的权重不是角色移动指令。

Unity 的 [1D Blending 说明](https://docs.unity3d.com/6000.0/Documentation/Manual/BlendTree-1DBlending.html)解释了单参数、Motion 阈值及预览。对原地走跑素材，不应指望从缺少前进位移的根曲线自动推导出正确行走速度。

完整移动循环要对齐左右脚接触相位，检查首尾姿势与速度。若身体每秒移动 4 米，脚步却按较慢步幅摆动，就可能滑步；只改变混合权重不能替代位移、周期与步幅的匹配。转向、起步与急停也可能需要独立片段，本篇不把所有运动压成三段循环。

这里的全身 Blend Tree 是扩展方案，**不把手臂 Cast / Hit 塞进速度树来假装完成移动系统**；本轮尚无完整角色走跑素材及脚步实验。

### 分层让部分身体执行不同任务

角色边走边施法时，可以让基础层负责移动，另一个层用 Avatar Mask 覆盖需要的上身骨骼，单独播放施法。Generic 应按实际 Transform 层级定义覆盖范围，并确认肩、手腕、装备及必要的躯干动作如何组合。

Override 层用于覆盖前面层的相应动画；Additive 则用于叠加变化，需要合适的参考姿势和兼容的动画属性，不能把一段普通全身施法随意改为 Additive 就当作完成上身叠加。还要设置层权重，并检查释放时手部指向与下身运动是否冲突。相关能力见 [Unity Animation Layers](https://docs.unity3d.com/6000.0/Documentation/Manual/AnimationLayers.html)。

分层增加了组合空间，也增加检查成本。本例先用单层完成播放与受击，之后拿真实全身动作再决定哪些部位可以分开。

## 打断要同时处理切换规则与已经开始的动作

### 能离开一个状态，与能打断一次过渡，是两回事

稳定播放 Cast 时，Any State → Hit 的条件满足，可以请求切到 Hit。Idle → Cast 还在混合时再受击，则是在问：**正在执行的过渡，是否允许另一个过渡接管？**

Unity 在这里还提供 Interruption Source 与 Ordered Interruption。前者影响把当前状态、下一状态的哪些过渡加入候选，后者影响按顺序查找到何处停止。Any State 过渡会先加入候选，所以 **Interruption Source=None 不能概括成“所有中断都禁止”**。本例保留 Any State → Hit，就是要分别检查稳定状态与混合中的受击。

这些规则依据 [Unity Animation transitions](https://docs.unity3d.com/6000.0/Documentation/Manual/class-Transition.html)。如果改为从 Cast 单独连到 Hit，就要重新考虑在 Idle → Cast 混合期间是否把下一状态的过渡纳入候选；不要只照抄当前图的 None。

本例关闭受击入口的自过渡，目的是避免同一受击状态反复重入；这不等于实现了所有连续受击规则。要覆盖受击中的再次攻击、死亡和控制效果，需要玩法优先级及更多组合验证。

还要检查 Has Exit Time。它表示按源状态的归一化播放进度决定退出时机，不是现实时间的固定延迟。若另建 Cast → Hit 过渡，却设置为等施法结束才退出，触发 Hit 之后就可能不能按需求及时切换；若同时设置退出时间和参数条件，两者都参与判定。

### 取消技能不能只让画面换个姿势

假设研究者起手时已出现手部蓄力效果，0.5 秒处准备释放。受击发生后，应先由玩法规则决定这次动作是否取消，再让表现处理相应变化：清理过期的施法请求、转入受击、停止或收尾蓄力效果，以及处理已释放内容的后续。

可以用一条关系理解：

```text
受击成立 → 玩法决定是否取消本次施法
         → 使本次动作的后续释放请求失效
         → 清理待消费的 Cast 请求，并请求 Hit 表现
         → 停止或收尾属于本次施法的蓄力效果
```

这是教学协作顺序，不是一段现成战斗系统代码。已飞出的投射物是否继续存在、受击是否打断霸体、取消是否退还消耗，都属于玩法规则，不能从 Animator 图自动得出。

事件和效果最好关联具体动作实例，防止上一轮迟到的回调影响下一轮。处理函数也应避免重复释放或重复清理。完整生命周期在[第 10 篇客户端接入]({{< relref "delivery-engineering/game-art-production-10-client-integration.md" >}})展开，这里先把动画交接需要的信息说清楚。

### 释放时点需要跟着动作时间一起理解

本例源第 61 帧对应 Cast 内的名义 0.5 秒、归一化位置 0.5。它不等于输入后固定等待 0.5 秒：状态可能延后进入，速度可能改变，也可能从不同偏移开始，途中还可能被取消。

动画师可以在交接文档中写释放标记，客户端再决定用游戏动作时间轴、配置数据或动画事件协调表现。若使用 Animation Event，可在导入片段的 Animation 标签展开 Events，将播放头移到对应位置，点击 Add Event，填写匹配的函数名，并在使用该 Animator 的对象上提供接收脚本。步骤见 [Unity 导入片段事件说明](https://docs.unity3d.com/6000.0/Documentation/Manual/AnimationEventsOnImportedClips.html)。

本轮没有添加接收脚本或执行事件实验。跳转片段、中断、循环、层混合及对象失活时，事件是否到达、属于哪次动作，需要在实际 Controller 与代码中验证。不要把“收到一个释放事件”直接等同于“这次技能仍有效且可以结算伤害”。

## 角色的位置由谁改变，要在制作之前约定

本例手臂根节点固定，Animator 关闭 Apply Root Motion，因此没有验证角色移动。扩展到完整角色时，需要明确位移来源。

**原地动作配合逻辑移动**时，动画主要提供姿态，角色移动系统依据输入、碰撞和玩法规则改变位置。动画师需要与程序对齐步幅、周期及移动速度，必要时调节播放速度或素材组合，避免脚步与世界移动脱节。

**使用动画根运动**时，片段携带位移或旋转，运行系统按约定提取并应用它。Generic 要确认选定的根节点与导入的 Root Motion Node；Humanoid 使用的身体与根变换处理另有规则，不能混用局部手臂的设置。引擎对根节点的要求见前面的 Generic 文档。

采用根运动仍要处理碰撞、地形、网络修正及技能允许的移动范围。有的项目会读取动画位移再交给角色移动系统，而不是任其直接穿过场景。关键是同一段位移由谁计算、谁应用：如果动画推进一次，逻辑又按完整距离推进一次，就可能重复移动。

交接至少写明：动作是原地还是带位移，哪个节点携带位移，前进方向和单位是什么，哪些阶段允许转向，以及取消后剩余位移怎样处理。Root Motion 是位移数据与应用方式的一部分，不替代完整角色控制器。

## 动作修改怎样回到游戏，接入后检查什么

假设释放显得太早，将源动作释放点从 61 改到 63。应回到动画原稿修改相关关键姿势和前后节奏，再输出新版本 FBX。只把特效延后两帧，却保留提前发力的手臂，会让两个表现各自正确、组合不一致。

修改后同时回查交接中的释放标记、片段时长、导入事件、退出时机和过渡。若总时长没变，固定的归一化释放位置已经变化；若把片段整体拉长，固定秒数和按比例时点也会产生不同影响。不能只替换文件就宣布接入完成。

建议保留来源版本，更新稳定的引擎输入路径，并保留其 `.meta`，再确认 Controller 和 Prefab 仍引用正确的片段。若改变了骨架层级、片段名称或导入配置，还要重新检查绑定与引用，不能只看 Project 面板文件名。
