沿着上一章的制作目标，假设研究者已经有了身体、衣服和法杖模型。现在让他抬手，静态模型还缺少一套关系：身体由什么驱动，肘部哪些点随上臂走，哪些随前臂走，动画师又通过什么把动作做出来？

仅把几根骨头放进模型里，表面不会自动获得合适的变形。把整个模型挂到一根骨头下，也只能让它整体跟随，无法解释弯曲处的变化。

**绑定与蒙皮要同时准备可操控的骨架、网格随骨架变化的关系，以及进入引擎后仍能成立的表达。** 本篇分别在 Maya 与 3ds Max 中走一遍制作，再把同样用途的产物导入 Unity。

> **读这篇之前**：先看[第 03 篇角色资产]({{< relref "delivery-engineering/game-art-production-03-character-assets.md" >}})，理解网格、拓扑、材质和导出物。这里聚焦形变基础；完整动作制作归 05，技能状态与生命周期归 10。

> **版本与证据范围**：工具步骤依据 Maya 2024、3ds Max 2024 和 Unity 6（6000.0）官方资料组织。简化手臂、权重数值、姿势组和目录为原创教学方案；关系图为原理示意。没有实际制作绑定工程、权重截图、FBX 或 Unity 场景，也未执行软件及设备实验。下文的观察条件和操作步骤均待实操，不代表已经得到合格角色。

## 先分清骨架、控制器、权重与绑定姿态

可以先把角色想成一张需要随动作变化的表面。骨架提供关节变换，蒙皮描述表面怎样受这些变换影响，控制系统帮助动画师方便地制作动作。

### 骨架提供层级，控制器提供操作入口

**变形骨架**由关节或骨骼节点组成。肩部带动肘部，肘部再带动手腕，这种父子层级让动作沿链传递。节点在制作软件中画成什么形状，不等于游戏里会多出一块可见骨头；真正有用的是层级、变换及与网格的联系。

**制作端控制器**可以是曲线、形状、辅助对象及其约束。动画师选择一个肘部控件旋转，背后可能由它驱动变形骨骼。控件的显示形状、约束和求解系统服务于制作，不要求原样出现在运行骨架里。

**游戏中的 Animator Controller**又是另一层：它组织动作片段和状态切换，不能因为也叫 Controller，就认为它会自动读取 Maya 的控制曲线或 Max 的控制系统。

### 权重描述一个点受哪些骨骼影响

蒙皮把网格上的点与骨骼联系起来。一个点可以只随上臂，也可以同时受上臂与前臂影响；数值描述各影响的参与程度。

例如，某点对上臂的权重是 0.75、对前臂是 0.25，表达的是它参与蒙皮变换时的分配。这不能直接理解成“把两根骨头的旋转角度按比例相加”。蒙皮还依赖绑定时的空间关系和实际使用的变形方法。

本例采用经典线性蒙皮，并让每个点的有效权重总和为 1。归一化是把参与的权重调整到这个总和；它能让数值一致，却不会自动保证分配符合人体运动。

### 绑定姿态保存的是建立联系时的基准

建立蒙皮时，系统需要知道网格与骨架当时怎样对应，才能把之后的骨骼变化用于表面。这份基准关系通常涉及绑定姿态及相关矩阵数据。

所以，给点分完权重以后，再随意移动关节、改变父级或把骨骼变换全部归零，可能改变正在被依赖的关系。这里的“恢复初始姿势”，也不等于把所有可见通道机械地填成零。

完整人体可以约定 A 姿势或 T 姿势等制作基准，但还要区分蒙皮基准、动画起始帧与引擎重定向要求。选什么姿势，需要相关环节共同确认。

## 按动作需求准备骨架，不先追求骨骼数量

研究者需要行走、转身、抬杖和收势，可以由这些动作反推：肩、肘和腕在哪里转动，躯干怎样配合，披片是否需要额外表达，法杖从哪里跟随。

根节点负责什么也要先约定。用于承载整个资产的根、骨架根、骨盆以及运行位移的来源，可能是不同对象。它们可以按项目设计合并或分开，但不能在导出、动画和客户端里分别猜测。

关节的位置与局部轴向都影响制作。肘部的旋转中心放偏，单靠刷权重不一定能修好；局部轴没有共同规则，镜像、动作制作和后续修改也会更难解释。应先检查结构，再讨论权重精修。

### FK 与 IK 解决不同的操控问题

**正向运动学（FK）**从父级往子级组织旋转：先转上臂，再转前臂，手的位置随之变化。它适合直接安排摆动、弧线和分段姿势。

**反向运动学（IK）**先给链的末端一个目标，再求解中间关节。例如希望持杖的手保持某个位置，可以用手部目标和弯曲方向控制去约束手臂。

使用 IK 还要检查弯曲方向、接近伸直时的稳定性和切换方式。FK/IK 混合、匹配及全身控制属于进一步的绑定系统；本篇只用一个肘部控制入口与短测试动作解释制作到导出的关系。

## 用一段简化手臂固定练习条件

先制作一段有足够分段的圆柱网格，模拟从肩到腕的表面。它用于观察权重变化，不是完整人体，也不继续假设上一篇已经存在一份研究者模型。

本例约定圆柱长 60 厘米、半径 4 厘米，沿长度分为 12 段，绕周向先取 8 段。长度上的分段给弯曲提供可移动的顶点环；如果只有两端的顶点，中间没有几何可用来形成预期过渡。

Maya 练习采用厘米、Y 向上，网格从 X=0 延伸到 X=60，中心高度 Y=100。骨骼位置采用下列**世界坐标目标**，不是要求把这些值直接填进每个子节点的局部 Translate：

| 节点 | Maya 世界坐标 X / Y / Z（厘米） | 本例职责 |
| --- | --- | --- |
| `root` | `0 / 0 / 0` | 固定的骨架根，不参与本例顶点权重 |
| `shoulder_r` | `0 / 100 / 0` | 上臂影响骨 |
| `elbow_r` | `30 / 102 / 0` | 前臂影响骨，保留轻微预弯 |
| `wrist_r` | `60 / 100 / 0` | 手腕附近的影响骨 |
| `hand_end_r` | `66 / 100 / 0` | 末端参照，不作为本例影响骨 |

</div>

层级按 `root → shoulder_r → elbow_r → wrist_r → hand_end_r` 组织。稍微预弯有助于明确讨论中的弯曲方向；它不是任何骨架都必须采用的固定尺寸。

将网格与 `root` 放到原点处的 `asset_export` 下，作为两个分支。制作控制器另外组织，避免把网格又挂到正在驱动它的肘骨下面。网格的移动、骨架的移动和蒙皮变化应能分别解释。

两套软件都以每点最多两个有效影响、三个主要影响骨作为练习条件。这个数量用于让过程易于检查，不是行业统一限制，也不是性能保证。

## Maya：建关节、Bind Skin，再检查实际权重

### 1. 在初始姿势中建立并整理关节链

新建工程，保存 `arm_rig_maya_v001.ma`。用多边形圆柱建立上述网格，把长轴调整为 X，确认长度分段和端点位置；先使用简单不透明材质，暂时减少纹理干扰。

切换到 Rigging 菜单集，使用 `Skeleton > Create Joints` 建立关节链，按表中的目标位置调整，并给节点命名。通过 Outliner 核对层级，打开局部轴显示，检查父子关节的朝向；需要时使用 `Skeleton > Orient Joint` 整理。

Autodesk 的 [Skeleton 菜单说明](https://help.autodesk.com/cloudhelp/2024/ENU/Maya-CharacterAnimation/files/GUID-5A485049-D0BD-4BBB-BE08-C3D502F17483.htm)给出了建关节与调整朝向的入口。此时先验证肘部沿预期平面弯曲，再恢复初始姿势；不要带着随意试出的姿势直接继续绑定。

### 2. 只把需要的关节加入蒙皮

选中 `shoulder_r`、`elbow_r`、`wrist_r` 与网格，打开 `Skin > Bind Skin` 的选项。本例采用：

- **Bind To：Selected Joints**，明确只使用已选的三个关节。
- **Skinning Method：Classic Linear**，建立经典线性蒙皮的对照路径。
- **Normalize Weights：Interactive**，编辑时保持权重归一化。
- **Max Influences：2**，并核对维持最大影响数量的相关设置与最终权重。

执行绑定后，检查网格上的 `skinCluster` 与影响列表，确认根、末端和控制曲线没有误入。自动生成的权重只是初始分配，下一步需要转动骨骼看它实际带走哪些点。

这些选项及其含义可对照 Maya 2024 的 [Bind Skin Options](https://help.autodesk.com/cloudhelp/2024/ENU/Maya-CharacterAnimation/files/GUID-CF2C698A-44BB-4CA0-BCB9-DB36500DA812.htm)。其中 Classic Linear 与 Dual Quaternion 是不同变形方法，不能只比较一组看起来相同的权重就假定结果一致。

### 3. 用画笔分区，再用数值检查过渡

选中网格，使用 Paint Skin Weights Tool，先选上臂影响骨，再选前臂和腕部，观察各自作用范围。这里的颜色通常表达**当前选中影响的权重**；一片黑色不一定表示这个点完全没蒙皮，它可能正受另一根骨骼影响。

先把远离关节的上臂和前臂区域分清，再处理肘部过渡。Replace 用来设定目标值，Add/Scale 等操作改变已有值，Smooth 则帮助平滑相邻分配；本例先以 Replace 和数值检查建立可解释结果，再少量平滑。工具操作可对照[权重绘制说明](https://help.autodesk.com/cloudhelp/2024/ENU/Maya-CharacterAnimation/files/GUID-99189E9D-237F-471E-A02C-BE6593B4828B.htm)。

可以按网格初始 X 位置选中整圈顶点，用下面这组数值练习。它只示范过渡，并没有经过实际变形验证：

<div role="region" aria-label="简化手臂的示例权重分布，可横向查看" tabindex="0" style="overflow-x:auto">

| 初始位置（厘米） | `shoulder_r` | `elbow_r` | `wrist_r` |
| --- | --- | --- | --- |
| X=0—20 | 1 | 0 | 0 |
| X=25 | 0.75 | 0.25 | 0 |
| X=30 | 0.5 | 0.5 | 0 |
| X=35 | 0.25 | 0.75 | 0 |
| X=40—50 | 0 | 1 | 0 |
| X=55 | 0 | 0.5 | 0.5 |
| X=60 | 0 | 0 | 1 |

</div>

需要精确核对时，在 Component Editor 的 Smooth Skins 页读取所选顶点的权重。编辑时注意影响锁定和归一化：改了某一列，其他列可能被重新分配，最后要读回全部有效影响并检查总和。Autodesk 的[数值调权重教学](https://www.autodesk.com/learn/ondemand/tutorial/adjusting-the-weighting-values)展示了这个位置。

如果所有点都硬切成上臂 1 或前臂 1，弯曲可能集中在很窄的一圈；把过渡摊得过宽，又可能让远离肘部的区域被拉动。不要只追求权重图颜色平滑，要回到实际姿势检查形状。

### 4. 给肘部增加一个制作控制入口

在保存的练习版本中，可以创建一个曲线控件，将它的位置和方向对齐肘部，并用上层组保留对齐基准。先选控件，再选肘关节，使用 `Constrain > Orient`，核对 Maintain Offset，建立旋转驱动关系。

转动控件，确认肘骨随动，网格通过蒙皮变形；再恢复控件的基准值。这条路径是“控件 → 骨骼 → 蒙皮网格”。约束选项可对照 [Orient constraint options](https://help.autodesk.com/cloudhelp/2024/ENU/Maya-CharacterAnimation/files/GUID-43481AAA-0513-4C02-8CE6-FAF5D0BEF96E.htm)。

控件不必直接成为影响骨。也不要同时在已有 IK、约束和关键帧之间叠加互相争夺的驱动；本例只有一个肘部入口，完整 FK/IK 控制系统另行扩展。

## 3ds Max：Bones 建链，Skin 负责权重关系

Max 路径与 Maya 完成相同的教学目标，但不是把 Maya 场景原样转换过去。保留独立 `.max` 原稿，按本机版本与 FBX 插件设置检查。

### 1. 先确认系统单位，再建立骨链

本例让 Max 的系统单位与显示单位均按厘米解释，并使用 Z 向上的场景约定。圆柱仍沿 X 从 0 到 60，高度在 Z=100，沿长轴保留 12 段；不要把 Maya 表中的 Y 高度直接当成 Max 的 Y。

在 Create 面板的 Systems 中选择 Bones，依次点击肩、肘、腕、手部末端，右键结束。对应位置可用肩 `0/0/100`、肘 `30/0/102`、腕 `60/0/100`、末端 `66/0/100` 作为世界坐标目标。

将三个主要骨段命名为 `shoulder_r`、`elbow_r`、`wrist_r`，末端小骨为 `hand_end_r`。建立独立的根辅助节点承载骨链，并与网格一起整理到导出层级，保持世界位置。骨链内部的编辑通过 Bone Tools 等骨架工具完成，不在蒙皮后随意重连。

Max 结束创建时生成末端 nub 骨的行为，可对照 Autodesk 的 [Bones System 步骤](https://help.autodesk.com/cloudhelp/2024/ENU/3DSMax-Modeling/files/GUID-E6164716-CFA9-4DE9-9976-F8A58850461F.htm)。名字相同不代表两套软件的局部轴相同，仍要确认实际弯曲方向。

### 2. 对网格添加 Skin，并明确加入哪些骨骼

保存 `arm_rig_max_v001.max`，选中圆柱网格，在修改面板添加 **Skin** 修改器，在 Parameters 的 Add 中加入三个主要影响骨。根辅助节点与末端 nub 不纳入本例的影响列表。

开启 Edit Envelopes，观察每根骨骼周围的包络。包络用于生成和调整作用范围，最终仍要看它赋给顶点的权重。先旋转肘骨，观察哪些环被带动，再恢复初始姿势。

本例先使用经典线性蒙皮，不启用 DQ 混合效果。网格本身的绑定关系保留在 Skin 中，不应为了“整理干净”把 Skin 直接塌陷掉，或在绑定后盲目 Reset XForm。

Autodesk 的 [Skin 使用步骤](https://help.autodesk.com/cloudhelp/2024/ENU/3DSMax-Modifiers/files/GUID-9596F6EF-3569-44F2-8D6C-6EB58C30BEDD.htm)说明了加骨、编辑包络和显式分配顶点权重的基本关系。

### 3. 调整包络后，用 Weight Table 检查数值

在 Edit Envelopes 中启用 Vertices，选中要修改的顶点环，选择对应骨骼，通过 Weight Properties 的 Abs. Effect 设置影响。需要跨多个顶点与骨骼编辑时，打开 Weight Table，对照前面的权重表检查。

Max 的 [Weight Table 文档](https://help.autodesk.com/cloudhelp/2024/ENU/3DSMax-Modifiers/files/GUID-9DE90E0E-C0E1-4E30-B4EC-BC4169917B28.htm)说明了批量修改顶点与骨骼权重的入口。本例检查每点的有效影响数量不超过 2、总和为 1，并确认没有远处或末端辅助骨的意外权重。

同样要注意自动归一化和锁定状态。把某一根骨的值改成 0.5，不保证另一根已经恰好是期望的 0.5；应读回结果，再比较弯曲姿势。

### 4. 控制入口与骨骼结果分开保存

最小检查可以先直接转动主要骨骼；若增加 Point 或形状控件及旋转约束，就通过该控制入口制作测试动作。不要在同一条链上无意叠加两套驱动。

控件、约束、修改器与制作说明保留在 `.max` 原稿中；实际交付需要哪些骨骼变换、Skin 数据和动作曲线，在导出时另行确认。控制对象便于制作，并不意味着运行端需要相同编辑工具。

## 用姿势检查权重，而不是只看一张静态色图

先在制作软件里形成一组可重复的观察：初始姿势、肘部轻弯与较大弯曲、前臂扭转，以及恢复初始姿势。完整人体还要加肩部抬起、手腕变化和躯干配合。

每次固定网格与骨架版本、相机角度和测试姿势，分别看：关节外侧是否过分拉长，内侧是否折叠，体积是否塌陷，远处顶点是否被带动，硬质扣具和服装是否发生不合理变形。

这些现象不一定全由权重造成：

- 弯曲中心不合理，先核对关节位置和局部轴。
- 没有足够顶点形成过渡，回到模型拓扑检查。
- 远处表面随肘部运动，检查影响列表与顶点分配。
- 只在扭转时明显失去体积，比较蒙皮方法、骨架辅助与形体修正方案。
- 只有导入后异常，则继续对照导出、绑定关系、动画曲线与引擎设置。

先缩小问题层次，再选择修改。一直 Smooth 权重，不能替代关节位置与网格结构的判断。

### 修正形变与披片，需要额外的制作和运行约定

可以通过重新分配权重、调整拓扑、增加辅助骨、采用适合的变形方法或姿势修正等方式改善结果，但每种方案都带来不同依赖。

Blend Shape 保存的是目标形状及其混合变化，可用于表情或姿势修正。制作软件中的“肘部弯到一定角度，自动驱动某个修正形状”还包含一层驱动关系；即使形状导出了，也不能假定原来的驱动器会在游戏中自动工作。

披片可以采用骨骼、模拟或简化表现；硬质法杖可以作为独立道具挂到手部，而不必像皮肤一样跨多根骨弯曲。换装件若要共享骨架，需要核对绑定基准、骨骼对应与实际引用，不能只比较节点名字。

更多蒙皮与 Blend Shape 的概念可读[已有渲染专题]({{< relref "rendering/unity-rendering-03-skeletal-animation.md" >}})。本篇不把其中任何方案作为已经完成的角色效果。

## 导出：把网格、骨架、蒙皮和测试动作一起说清

为了检查制作关系是否传到下游，本例准备一个很短的动作：帧率约定 24 fps，第 1 帧为初始姿势，第 13 帧让肘部沿已确认的弯曲轴转动约 60°，第 25 帧恢复初始姿势。对实际驱动对象设置关键帧，根节点保持不动。

若直接驱动骨骼，就对骨骼记录；若由控件或 IK 驱动，则对制作端入口记录，再准备输出骨架的采样结果。Maya 与 Max 的局部轴可能不同，60° 表达测试目标，不要求两边照抄同一个 Rotate Z 数字。

原稿和导出物可以这样区分，所列文件均待实际制作：

```text
ArtSource/Researcher/Rig/
  Maya/arm_rig_maya_v001.ma
  Max/arm_rig_max_v001.max
ArtExport/Researcher/Rig/
  Maya/v001/arm_rig.fbx
  Max/v001/arm_rig.fbx
  rig-handoff.md
GameProject/Assets/Art/Researcher/RigTest/
  arm_rig.fbx
  Materials/
  Controllers/
  Prefabs/
```

两套导出分别保留作对照；接入练习先选其中一份。不要把两个不同来源的文件轮流覆盖后，还声称在验证同一个版本。

### Maya：Skins 与骨骼曲线各自需要导出

选择预定的导出层级与所需网格、骨架，使用 `File > Export Selection` 选 FBX。明确包含 **Deformed Models > Skins**；若采用 Blend Shape，再检查相应输出。没有蒙皮信息，只有网格和会动的骨架，仍不足以得到预期表面变化。

为本例的短测试启用 Animation，并核对 Bake Animation 的范围为 1—25、Step 为 1。烘焙在这里指把制作驱动求值为所需动画曲线，与上一篇高低模贴图烘焙是不同用途。

不受目标支持的约束需要通过采样等方式形成可消费的骨骼结果；不能只导出控制曲线就期待接收端重建整套绑定系统。若导出选项不能覆盖所用求解与驱动，应先在制作端准备并检查输出骨架，再导出。

Autodesk 的 [Maya FBX 导出选项](https://help.autodesk.com/cloudhelp/2024/ENU/Maya-Basics/files/GUID-FE8DBEAA-C2DD-43B3-9933-4BA4CDDEAA89.htm)分别说明了 Skins、Blend Shapes 与动画烘焙。实际导出后仍要看警告，并核对输出曲线，不能用勾选一个选项代替观察。

### 3ds Max：保留 Skin 交付数据，并采样所需驱动

保存 `.max` 原稿，导出选定的网格与骨架为 FBX。在导出 Animation 相关设置中确认 **Deformations > Skins**，并为本次短测试核对动画与 Bake Animation 的范围、采样步长。

如果使用约束、IK 或其他控制系统，重点检查它们的结果是否已经成为目标可以使用的曲线。需要形态修正时，再核对 Morph 等内容，不能默认 Skin 修改器以外的全部效果都会保留。

Max 的 [FBX Animation 说明](https://help.autodesk.com/cloudhelp/2024/ENU/3DSMax-Interoperability/files/GUID-31EA2A4F-A126-498B-96E8-31811522738A.htm)区分了动画采样和 Skin/Morph 变形输出。与 Maya 一样，应记录插件版本、单位、轴向和实际导出范围，再在下游核对。

### 先检查导出物，再解释正式交付

可以在干净场景中重新导入 FBX，检查网格、影响骨、初始形状和测试曲线。它有助于发现输出问题，但同一软件往返不等于 Unity 已经通过。

本例一份 FBX 同时带模型与短动作，便于验证关系。正式制作可以将带蒙皮的角色资产与多个动作文件分开，但要稳定骨架与绑定约定；具体动作交付在第 05 篇展开。

## Unity：选择正确的 Rig，再验证实际蒙皮与播放

把选定来源的 `arm_rig.fbx` 放进项目。Model 页中的单位、轴向与尺度检查沿用上一篇：本例 60 厘米的网格应对应约 0.6 个米制场景单位，Maya 的 Y 向上与 Max 的 Z 向上还需要经过导出/导入转换。检查实际结果，不靠改多个父节点缩放去掩盖差异。

### 1. 局部手臂使用 Generic，不冒充完整 Humanoid

在 Rig 页选择 **Animation Type：Generic**，Avatar Definition 使用 **Create From This Model**，核对根节点为本例约定的骨架根。局部手臂缺少完整人形结构，不应为了套用一个选项而强行配置为 Humanoid。

完整研究者若采用 Humanoid，需要另行配置有效的人形骨骼映射和姿态，检查实际重定向结果；Generic 也不会因为节点命名接近，就自动复用任意另一套骨架的动作。

首次对照时先关闭 Optimize Game Objects，便于观察导入层级与挂点。后续采用优化时，再按需求核对 Extra Transforms to Expose；不要在层级变化后继续假设旧的查找路径仍然有效。

Skin Weights 选择能够保留本例每点两个有效影响的配置，例如 Standard（4 Bones）；它只说明这个数量上限不会把本例的两个影响按数量截掉，不是完整一致性保证。若使用 Custom，还要核对权重阈值；运行端的质量配置也要一并记录。

Unity 的 [Rig 导入手册](https://docs.unity3d.com/6000.0/Documentation/Manual/FBXImporter-Rig.html)说明了这些字段。四根影响不是所有项目的固定上限，导入保留了什么、运行实际采用什么，需要分别检查。

### 2. 确认是带蒙皮的网格，而非只有普通模型

将模型放入观察场景，检查相应对象有 **SkinnedMeshRenderer**，并核对网格、材质和根骨引用。如果只有普通 MeshRenderer，或骨架会动而表面不跟随，应先沿蒙皮输出与导入关系排查。

材质建立沿用上一章；本例用简单不透明材质，先看形状和运动。不要在还没确认蒙皮数据时，同时引入复杂透明、布料与特效。

随后检查 Bounds 是否能涵盖需要观察的姿势。模型在某个镜头下消失，也可能与包围范围和剔除有关，不能仅凭画面缺失就断定权重错误。相关职责见 [Skinned Mesh Renderer 手册](https://docs.unity3d.com/6000.0/Documentation/Manual/class-SkinnedMeshRenderer.html)；是否调整范围或更新策略，要结合具体动作与成本判断。

### 3. 先在预览里检查短片段，再进入场景播放

在 Animation 页启用动作导入，从源时间范围定义名为 `skin_test` 的片段，核对 1、13、25 帧所对应的姿势和帧率解释。首次对照可以暂时关闭动画压缩，减少一个影响因素；项目最终设置再另行验证。

播放并拖动预览，比较初始、中间弯曲与恢复姿势。这里的目标是骨架曲线与表面变化有没有传过来，还没有验证最终角色动作的表现力。Unity 的[Animation 页说明](https://docs.unity3d.com/6000.0/Documentation/Manual/class-AnimationClip.html)提供了片段划分与预览入口。

接着在 `Controllers` 创建 `RigTest.controller`，将 `skin_test` 拖入 Animator 窗口成为状态，确认它是默认状态；把控制器赋给导入模型根上、与骨架路径相匹配的 Animator，并核对 Avatar。状态入口见 [Animation States](https://docs.unity3d.com/6000.0/Documentation/Manual/class-State.html)。

本例不测试位移，先关闭 Apply Root Motion。可以用外层对象包装为 `RigTest.prefab`，但保持 Animator 与骨架的相对路径；不要把组件随意移到另一层后继续假定动画路径不变。

保存观察场景，让相机覆盖整段手臂的姿势范围，进入 Play 模式。分别确认：状态在播放、关节有变化、表面随动、恢复姿势可理解。即使这一步完成，也只是编辑器中的传递验证，正式 Player、目标设备、角色握杖和施法仍需继续检查。

### 4. 把法杖接到手部，先对齐握持点

在完整角色的腕部下可以约定 `weapon_socket_r`，记录其局部位置与朝向，客户端再把法杖模板接到这里。本例若先用手臂练习，也可以准备同用途的挂点观察相对运动。

上一篇法杖原点在杖底，握持位置距杖底约 100 厘米；因此把法杖局部位置直接置零，并不意味着手就握住了杆。需要用握持标记或包装偏移，让法杖的握持位置与手部挂点重合，再检查朝向。

挂点可以作为骨架输出的一部分，也可以在引擎组装中创建，但要固定由谁维护。它没有顶点权重，不表示运行时不需要它；同样，它没有出现在某个蒙皮骨骼列表里，也不足以判断它是否仍存在于 Transform 层级中。

## 修改骨架以后，怎样让下游知道需要重验什么

如果只是调整肘部的权重，先保留当前原稿版本，重新输出同一骨架与网格的蒙皮信息，再在 Unity 更新既有资产，按相同姿势与镜头复查。对比的是版本与条件，不只是截图看起来有没有变。

如果移动了关节、改了骨骼朝向或重组层级，就要进一步检查绑定基准、旧动作、动画路径、装备挂点和换装件。动作曲线仍能读取，不代表它在新骨架上表达了相同姿势。

如果重做了网格拓扑，旧权重的顶点对应也需要重新确认。工具可以帮助复制或转移权重，但转移后仍要按姿势检查，不能把“工具没有报错”当作形变验收。

可以把交接说明写成几项具体内容：

- **本次基准**：网格版本、骨架版本、单位、轴向、初始姿势与导出根。
- **运行数据**：所用影响骨、蒙皮方法、权重数量约定、是否有 Blend Shape 或其他修正。
- **使用接口**：动画采用的骨架、挂点路径、局部朝向、法杖握持偏移。
- **检查范围**：实际完成了哪些姿势、软件往返、Unity 预览、Play 或设备检查，哪些仍待执行。
- **变更影响**：这次改的是权重、网格、骨架还是控制端，通知哪些依赖它的制作和接入。

本文练习尚未实际制作，因此目前只能把这些字段作为交付设计，不能填入虚构的“全部通过”。

## 用三个问题检查自己有没有把关系串起来
