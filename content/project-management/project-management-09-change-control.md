材料快准备完时，有人提出：“既然都要培训，顺便把物品损坏怎么处理也讲一下吧。”这个要求可能有价值。但如果组织者直接让准备者加几页，讲师、参加者、规则负责人和检查人可能仍按原来的安排工作。最后材料变了，时间没有变，验收条件也没有人重新确认。

**变更控制要解决的，是一项新决定怎样进入共同承诺：先看清改变了什么和会影响谁，再由有权的人作出取舍，并让执行与检查都使用新的约定。** 它既允许合理调整，也让不能承受的调整及时停下来。

本篇需要的基础只有三项：原来答应交什么、有哪些限制、谁有权决定。前两项见 [PM-04 目标与验收]({{< relref "project-management/project-management-04-goals-scope-acceptance.md" >}})，权责见 [PM-02]({{< relref "project-management/project-management-02-roles-responsibility-authority.md" >}})。没有读过也可以跟随下面的例子。

> 全文使用虚构培训，沿用 12 名参加者、90 分钟、600 元直接支出上限，以及常规借用登记和缺必要信息处理的范围。新增专题、改期及相应确认记录是两个独立的教学分支，不是作者经历，也不表示此前文章中的风险已经发生。日期用相对工作日表达，实际使用时需替换为具体日期与时段。

## 一、先找原约定，才能判断改变了什么

APM 将 change control 定义为：捕获、评价对已批准基线的变更请求，再决定批准、拒绝或推迟处理。[1] 这里的**基线**可以先理解为“已经确认、用来判断偏差和评估新要求的那一版约定”。它应当能被找回，有版本、确认人和确认时间。

小型内部培训不必先建立复杂系统。项目说明 v1.0，加上相互对应的材料清单、时间安排和验收条件，就可以构成可追溯的依据。没有人确认过的讨论稿，不能只因为文件名带着“最终版”，就变成大家已经承诺的事情。

基线也不等于永远不能改。它保留一个参照，让人说得清“从哪一版改到哪一版、为什么改”。保留旧版与变更记录，是为了理解决定和结果；当前执行入口则应明确指向已生效版本，避免多个版本同时指挥工作。

还要区分**重新预测**和**改变承诺**。例如，最新估计显示材料会晚一天，这个预测应立即如实更新；它不代表交付日期已经获准延后。记录中应同时看得到原承诺、当前预测、偏差及待决方案。把计划日期直接改成最新预测，会掩盖尚未解决的承诺问题。

本篇讲的是项目约定的变更控制。组织变革中如何帮助人员采用新制度，是更大的议题；APM 也明确区分这两种语境。[1]

## 二、先分类，再看影响，不能靠名称免除处理

有人称自己的要求是“澄清”，有人称它是“修一个小问题”。这些名称可以帮助讨论，却不能替代对原约定的检查。

| 收到的要求 | 怎样判断 | 本培训中的教学例子 |
| --- | --- | --- |
| 澄清 | 把已有约定解释清楚，没有改变接受条件或新增义务 | 把“信息完整”写明为既有规则中要求的借用人、编号、数量和归还时间；需核对这些原本就在约定中 |
| 缺陷修正 | 当前结果不符合已确认要求，需要恢复符合性 | 现行规则要求填写物品编号，讲义却漏掉该字段，需要修正并复核 |
| 新增或替换要求 | 新增交付物、能力目标、覆盖对象，或替换原来承诺的内容 | 新增损坏处理专题，涉及新的规则、练习及检查要求 |
| 优先级调整 | 内容可能没变，但顺序、资源占用或交付批次改变 | 把原定下周的材料检查插到今天，可能挤占其他已承诺工作 |

两条边界尤其容易忽略。

第一，**缺陷属于原范围，不代表修复没有代价，也不代表可以跳过发布、合同或组织要求的审批。** 如果补漏必须重印、加钱或推迟交付，就要按相应权限处理这些影响。问题记录与变更记录可以互相链接，不需要在两张表里编出两份互相矛盾的计划。

第二，**意见不一致时，不要单方面认定是澄清。** 如果一方原来认为只交纸质讲义，另一方认为还包括可检索电子版，就先核对已确认材料。仍无法证明双方已有一致约定时，把差异和待决定事项写出来，再讨论如何处理，不能用“你应该早就知道”代替决定。

轻量流程的依据是影响小、授权清楚、可恢复，而不只是工作看起来少。一个字的修改也可能改变金额或验收标准。

## 三、影响分析要沿着工作传递下去

《项目管理之美》第14章讨论“探讨变动的影响”和“管理变动（变动控制）”，强调变化需要关联目标、考虑受影响的人和工作，并在接受后更新进度与说明文件。[2] APM 的公开流程也要求检查范围、质量、时间、资源、成本、风险与收益等方面。[1]

可以把这些内容收束成一次具体追问：**如果答应这个要求，谁正在做的什么工作必须改变，谁后面接收的东西也必须改变？**

在第一个教学分支里，参加者代表希望增加“物品损坏后的处理”。组织者先记录这个建议，尚未答应纳入本期。只估计“再做几页讲义”，会漏掉下面的影响：

| 要核对的对象 | 本次新增专题会带来的问题 | 判断所需的信息 |
| --- | --- | --- |
| 目标与范围 | 原目标是常规登记与识别缺项；现在是否还要求能够处理损坏？ | 发起人说明新能力为何必须在本期获得，不能只说明内容有用 |
| 规则与材料 | 损坏处理涉及哪些现行规则，谁能确认？ | 规则负责人提供依据；准备者列出新讲义、练习与复核工作 |
| 课堂与检查 | 在 90 分钟内增加专题，会挤占什么？ | 讲师重排议程，并核对原独立练习和反馈能否保留 |
| 人员与日期 | 谁做新增工作，何时有空，影响哪些已约定事项？ | 由实际承担者估计投入；相关负责人确认资源和时间 |
| 成本与外部协作 | 页数、印量、配送或场地安排是否改变？ | 重新询价并核对订单状态，不能把未用额度视为自动授权 |
| 验收与风险 | 新能力如何检查，规则未明确时是否会误导参加者？ | 新标准、检查责任与未解决问题；不可因加了内容就默认学习效果提高 |

这张表不要求所有项目都写六份报告。它让分析者不把自己的工作量当作全项目代价。涉及不同专业时，要找承担者判断；信息不足就写“待确认、由谁补、何时补”，不能把空白填成零。

影响也包括切换和返工：已写材料可能重做，已下订单可能需要协商，讲师可能需要重新熟悉内容。已经付出的成本应如实记录，但是否继续投入仍要看未来代价与价值，不能仅因已经做了一半就自动批准。

## 四、把取舍交给有权决定的人

评估之后应当出现选项，而不是只留下“同意还是不同意”。这个教学分支至少有三种处理方式：

1. **保持本期范围。** 按原定 90 分钟完成常规登记、缺项处理及检查；损坏问题仍交现行规则负责人处理，不编造培训外的替代制度。
2. **调整本期范围与资源。** 先确认规则、增加工作和检查，再重估时间、费用及人员安排；如果必须延长或删减原内容，就明示改变哪些承诺。
3. **作为后续专题候选。** 留下问题、受益者与下一步调研人。它尚未获得开课日期、预算或资源承诺。

方案 2 不是简单地“在 90 分钟后再加一点”，方案 3 也不是已经承诺“下期一定做”。保留未选方案及关键理由，可以帮助下一次提议者理解决定。

谁拍板，取决于原有授权。执行者可以在授权范围内调整做法；涉及目标、验收、跨团队资源、合同或预算的变化，应由拥有相应权限的人决定，必要时分别获得相关确认。发起人同意培训改期，并不自动取得参加者所属团队的时间；组织者也不能替供应方承诺费用不变。

因此可以事先约定一张简短的权限表：哪些调整执行者可直接处理，哪些由负责人决定，超过什么边界必须升级；决定人无法及时回应时找谁、最晚何时需要答复。小团队可以用简短会谈和书面记录完成。多人受影响、难以回退的事项则需要更完整的评估，流程强度应与影响相称。

紧急情况也要有明确权限。例如先暂停发放明显错误的材料，可以是预先授权的控制措施；它并不自动授权改写制度或追加采购。实际采取了什么、为何先做、影响了哪些承诺，仍需及时记录，并由相应权限人处理后续决定。不能把事后补记录当作任何人都可以先实施的通行证。

## 五、一份记录，连接决定与执行

先看新增专题的处理。下面的评估与决定全部是教学设定：规则尚未核清，新增工作与时间也没有得到承担者确认。

| 字段 | CR-01：新增损坏处理专题 |
| --- | --- |
| 原依据 | 培训约定 v1.0：12 人、90 分钟、直接支出上限 600 元；不含损坏处理专题 |
| 请求及理由 | 参加者代表希望了解损坏处理；需要补充实际需求及规则依据 |
| 影响结论 | 规则、新材料、课时、资源与验收尚未确认，不能按原承诺直接加入 |
| 决定 | 发起人拒绝纳入本期；保留为后续专题候选，不承诺日期与资源 |
| 未选方案与原因 | 本期扩范围尚无可执行安排；单纯压缩原独立练习会损害原目标与检查 |
| 跟进 | 组织者向提议者和讲师说明决定；规则负责人接收问题线索，组织者在本期结束后确认是否有立项讨论条件 |
| 当前基线与关闭依据 | 本期仍按 v1.0；相关执行者确认不插入新专题后，关闭本次请求处理。后续专题候选单独保留，不把它标成已交付 |

现在换一个**独立的改期分支**，看批准后的记录。另设原课堂在第 7 个工作日，部分参加者出现时间冲突；新时段改为第 8 个工作日，仍为 90 分钟。材料准备仍采用第 1—5 日安排，不因改期而省掉最终复核。

本分支进一步假定：12 名参加者及其时间安排负责人、讲师、场地协调者均已确认新时段；材料与印送可以在课前完成；供应方确认调整不加价；各项直接支出预测合计仍不超过 600 元。这里的确认是演练输入，不能照抄成真实项目的证据。

| 字段 | CR-02：课堂由第 7 日改到第 8 日 |
| --- | --- |
| 原依据与改变 | v1.0 的课堂日期为第 7 日；只改到第 8 日对应已确认时段，90 分钟、人员、内容和验收条件不变 |
| 目标与代价 | 解决已发现的参加时间冲突；能力检查相应晚一个工作日，发起人确认该影响可以接受 |
| 评估记录 | 链接参加、讲师、场地、材料及供应方确认；人员投入安排已确认，费用预测重新核过，没有新增直接费用 |
| 决定与生效 | 发起人在资源确认齐备后批准；组织者当天发布约定 v1.1，从发布时起执行新日期，保留 v1.0 和本次决定 |
| 要更新的对象 | 项目说明、日程邀请、场地预订、材料交接及印送时间安排、能力检查日期；讲义中若出现课堂日期也要同步 |
| 通知与责任 | 组织者向参加者、讲师、规则负责人、场地及供应方联系人发出新安排；要求关键交接方确认所用版本和下一步动作 |
| 实施检查与当前状态 | 已批准，执行更新待核验；组织者检查各入口的新日期、旧邀请处理情况和关键接收方确认后，才可标记变更已落实 |

批准是一次决定，落实则需要后续事实。即使这条改期已经落实，培训也尚未举行，不能把培训或整体验收一起标成完成。

如果某方没有回应，就记录“待确认”，明确负责人和处理时限。**发出通知只能证明通知动作已做，不能证明对方已经理解并按新版行动。** 不必每次都召集所有人开会，但关键交接点要有能够核对的确认。

## 六、更新一条执行链，避免只改审批单

《项目管理之美》第7章讨论规格说明书如何表达目的和决定；当现实与目的改变时，说明文件也需要反映这些变化。[3] 对通用项目而言，变更落实可以按下面这条链检查：

```text
请求与原依据
  ↓
影响、选项与决定记录
  ↓
已批准的新约定及生效条件
  ↓
具体工作、人员时间、交接与检查标准
  ↓
受影响者确认 → 执行结果核对 → 关闭变更跟进
```

拒绝或暂缓的请求停在决定处分流，不能进入实施。暂缓还要写明重新考虑的条件和负责人；如果某个条件迟迟不满足，也要在约定时间复查，而不是永久挂着一个没人处理的状态。

批准后应更新受影响的对象，不必机械重写所有文件。涉及日期就核对日程与交接；涉及交付物就核对工作分解和验收；涉及费用就核对预算、采购及支付安排；涉及假设就回看 [PM-08 风险与问题]({{< relref "project-management/project-management-08-risks-and-issues.md" >}})。保留旧版是为了追溯，明确新版入口是为了执行。

还要核对新决定是否可行。如果批准后又发现场地冲突，当前预测和问题状态应及时更新，重新提出处理方案。不能因为审批结束，就把仍不可执行的计划写成已解决。

这些做法也适用于迭代工作。尚未承诺的候选工作可以更频繁地调整；但对正在执行的交付目标、受影响团队及外部承诺，仍需要看见变化与代价。控制程度可以不同，共同约定不能在不知情中被替换。

## 七、练习：看到两个未通过的人，应该改哪张表

沿用本系列的整体验收条件：三类交付物符合要求，并且 12 人全部通过约定的能力检查。现在检查结果是 10 人通过、2 人未通过，组织者提出：“把目标改成大多数通过就行，这样可以收尾。”

先写下四件事：

1. 当前结果和原约定是什么，哪些记录必须保留？
2. 这是结果记录勘误、缺陷处理，还是改变验收条件的请求？
3. 除了改变标准，还有什么处理方案，需要哪些时间与资源？
4. 即使有权的人同意新的接收安排，哪些旧事实仍不能改写？

参考判断：10/12 是当前检查结果，按原条件整体验收未通过。先确认记录准确，并找出两人需要的支持；补充指导、复查或其他安排需要明确责任、时间与资源，不能默认包含在原 90 分钟与 600 元内。把目标改成“大多数通过”会改变原验收条件，需要明确理由、影响与权限，不能作为记录勘误直接覆盖。

如果有权的人决定采用新的接收安排，应同时保留原目标未达成、新决定及未完成事项的后续责任。它不能把两人的未通过改成通过，也不能证明原培训目标已经实现。外部合同、制度或强制要求若不允许调整，内部决定不能替代那些要求。

## 八、可复制的简版变更记录

```text
编号／提出人／提出日期：
原约定版本及相关条目：
建议改变什么，为什么现在需要：
分类与依据；有无尚未确认的分歧：
受影响的目标、工作、依赖、人员、时间、费用与检查条件：
已核实的事实／估计与假设／待补信息、负责人和期限：
选项及代价（包括保持现状），建议选项：
决定人及权限依据／决定日期／批准、拒绝或暂缓：
决定理由／未选方案／生效或重审条件：
需要更新的文件、任务和交接／负责人／完成期限：
通知对象、关键确认与未回应事项：
实施检查证据／未解决问题／变更跟进关闭人及日期：
```

先用一件正在发生的变化填这份记录。若仍说不清原约定、谁决定或谁会受影响，就先补齐这些信息；不必为了显得正式先搭建一套复杂审批系统。

2. Scott Berkun：《项目管理之美》，机械工业出版社，2009，ISBN 9787111259527。第14章“中盘战略”，重点为“探讨变动的影响”“管理变动（变动控制）”，并参考“打破承诺”对重新协商承诺的讨论。书中的软件团队情境用于理解影响和沟通，不把所有变更都必须经过同一委员会或固定流程作为通用规则。
3. 同书第7章“撰写优秀的规格说明书”。使用其对说明文件目的、共同参照与随决定更新的讨论；不把特定团队的文档分工、会议形式或估算倍数推广为要求。

本文的分类表、权限建议、两份变更记录及练习是面向通用协作的教学整理，未冒充书中原表或组织标准。PMBOK 的采用版本与原文位置仍待核实，本文不标注未经核对的章号。
