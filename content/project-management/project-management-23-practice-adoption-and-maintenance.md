一份新说明已经写好，熟悉它的人也能照着完成工作。后来，换了一位接手者，规则又更新了一次：新成员从旧消息找到副本，原维护者以为内容负责人会更新，内容负责人却以为页面只是一次性材料。

这个假设情境中的缺口，是一项做法没有接上持续使用和维护。**要让下一位成员继续做对，除了留下步骤，还要说明何时使用、从哪里进入、谁处理变化，以及旧办法怎样退出。**

本篇面向要把一项改进交给团队持续使用的人。[PM-22]({{< relref "project-management/project-management-22-retrospectives-and-actions.md" >}})已讨论怎样选择一次试用和复查行动；这里进一步判断：是否值得维持共同做法，需要维持到什么程度，何时应当改选。基础概念在文中解释，不要求先用某种管理软件。

## 一、先确认值得重复的究竟是什么

“沉淀”可以是一条交接约定、一份检查清单、一个受维护的入口，也可以是工具中的规则。它们共同承担的是：在某类问题再次出现时，帮助使用者找到当前可用的做法，并在例外出现时找到处理者。

先写出一个具体的重复需求，例如“每次开始编写同类材料前，都能取得这次适用的规则”。“建知识库”“全面标准化”只说明载体或愿望，还没说明哪些工作值得持续投入。

Berkun 第10章建议从明确问题、比较替代办法和低风险试用开始，约定评估时点，再根据试用所学调整范围；流程还应包含修改或停止自身的机制。[1] 因此，一次顺利不能直接支持全员推广。应先检查下一组使用者的任务、输入、权限和支持条件是否与试用相近。

格鲁夫第3章讨论标准化时，同时保留因时制宜地寻找更好方法的空间。[2] 一致性可以减少每个人重新猜测，但一致地执行错误或过时的规则，同样会放大问题。适合固定的通常是共同输入、必要检查和交接结果；尚需判断的部分，要留下判断依据与升级入口。

没有重复需求、影响很小，或者现有办法已经足够时，可以只保存一次决定及其依据。低频但后果严重的事项则另作判断：发生次数少，不等于必要的验收或保护可以取消。

## 二、用相同目标比较需要多重的做法

继续借用PM-22的材料交接主题，但只作**未来维护方案的虚构推演**：假设后续确有多次同类交接、涉及不止一位发送者，各次适用规则能由规则负责人确认，并且各方愿意讨论安排一位入口维护者。没有假定PM-22的试用已经执行，也没有新增原培训的时间、费用或验收承诺。

共同目标是让编写者在开始前取得本次适用的规则，并让后来的复核者知道当时采用哪一版。比较以下三种办法：

| 选择 | 怎样接到工作 | 付出的代价与尚存缺口 |
| --- | --- | --- |
| A：保留简短的交接消息约定 | 每位发送者核对入口、版本、用途和异常联系人；每次交接保存当时依据 | 建立成本低，但每次都要重复维护，发送者增多后容易出现不同副本 |
| B：维护统一来源页，交接仍记录当时版本 | 页面指向当前适用规则及历史记录；发送者引用它，接收者核对本次版本 | 少复制多份说明，但增加页面维护、可访问性检查和版本切换工作；统一入口失效可能同时影响多人 |
| C：在现有工作工具中增加自动检查 | 例如提示缺少规则编号、来源链接或未确认状态，再由相关人处理 | 需要实现和维护；能检查字段，不自动证明规则内容正确、接收者理解或真实任务完成 |

在上述“重复交接、多个发送者、规则可确认”的假设下，可以优先为B准备有限试用：它集中处理副本维护问题，同时保留每次交接的具体依据。接受的代价是增加一个需要持续照看的公共入口；它不能取代规则负责人或专业复核。

**维护投入和备用处理未落实前，B仍是候选。** 先沿已确认的交接安排工作，不把一项尚无维护者的新页面宣布为唯一入口。若后续实际上很少交接、参与关系简单，A可能更合算。只有检查对象足够明确、重复检查负担已有记录，并能安排维护和失败处理时，才考虑C；规则含义频繁变化时，自动化会把变化成本转到工具维护者身上。

这里按目标和条件选做法，不给三种方案编造收益分数。比较成本时，应同时看编制说明、教学、日常使用、维护、等待和异常处理；减少发送者几次复制，却增加接收者长时间等待，并不一定值得。

## 三、一页说明，把使用者和维护者接起来

把B写成下面这份草案。它是本文设计的示例，尚未获准试用。实际采用时须确认具体人员、可用时间与日期；不能因表里有角色，就认定对方已经承担责任。

| 字段 | P-01：材料规则入口维护草案 |
| --- | --- |
| 问题与范围 | 同类材料多次交接时，减少来源分散和版本不明；只覆盖已由规则负责人确认的规则，不替代内容正确性及整体验收 |
| 使用触发 | 开始一次新的材料编写、材料依据有变更，或接手正在进行的编写工作时核对 |
| 进入与输入 | 从现有任务说明进入统一来源页；页面提供适用范围、规则版本、确认记录、来源链接和异常联系人 |
| 使用步骤与产出 | 发送者说明本次适用版本与用途；接收者确认可访问，交接记录保留该版本及依据；有冲突时不自行猜选 |
| 规则责任 | 规则负责人确认内容、适用范围及变化影响；页面维护者不能自行改变业务要求或验收条件 |
| 入口维护 | 拟由组织者安排维护者更新链接与状态，检查实际访问；维护者缺席时，由有权者安排替代者或暂时采用已确认的人工核对路径 |
| 学习与支持 | 维护者演示正常交接和来源冲突；使用者独立完成一次练习，指出版本与求助入口，记录仍需的帮助 |
| 复查与投入 | 首次获准试用后一起复查，扩大到新角色前再核对；同时约定最长复查间隔。具体日期、间隔及双方投入待确认，未确认前保留草案状态 |
| 异常与退出 | 规则未确认、入口不可用或两处依据矛盾时暂停依赖该输入的工作并联系相应负责人；替代路径也须明确有效版本。停用须安排在办工作和历史记录的接手方式 |

这张表分开了两种容易混淆的责任：**谁能改变规则，谁负责把已确认的规则交到使用者手中。** 同一个人可以兼任，但责任仍需说清。跨团队采用还要取得受影响团队对职责和投入的确认，不能由页面维护者替所有人承诺。

说明应放在工作发生的位置。若任务入口还链接旧副本，仅在另一个文件夹里建一份新文档，使用路径就没有完成切换。也不必把全部历史贴在首页：当前使用说明简短，历史决定与版本依据通过链接可追溯即可。

## 四、让人会用，也让人知道何时不能照做

格鲁夫第16章强调培训内容应贴合组织实际工作，并区分新成员学习已有工作与老成员学习新做法。[3] 对本例而言，两类学习需求不同：新接手者需要理解完整交接，老成员可能只需要弄清这次变化、受影响的工作和新异常路径。

可以用两道任务核对，而不只让大家读完后回复“收到”：

1. **正常输入：** 给出一项获准的练习任务，让使用者从任务入口找到适用规则，指出版本和确认依据，留下交接记录。观察哪些步骤独立完成，哪些需要旁人提示。
2. **异常输入：** 在隔离的教学材料中放入两个相互冲突的来源，让使用者说明哪里不能确定、下一步联系谁。练习不修改正式材料，也不制造真实交付风险。

发现“不会用”后要回到实际障碍：是链接打不开、术语不明、没有权限、责任未定，还是步骤确实难懂。增加培训不能修复访问权限，也不能代替有权者确定规则。

格鲁夫第10章讨论不同控制方式与环境条件的匹配，并不把某一种方式视为处处适用。[4] 本文据此保留明确约定与共同判断的配合：可重复的部分写清步骤，含义不明的部分让人能提出异议并获得决定。不能把未采用一项做法直接解释为态度差，也不能用“相信大家”替代必要的版本和责任记录。

## 五、规则变了，要处理正在做的工作

维护不只是把页面上的日期改新。假设规则负责人准备发布R3，而部分材料仍按R2编写，至少需要连接四件事：

| 环节 | 必须回答的问题 | 本例的处理边界 |
| --- | --- | --- |
| 判断影响 | 哪些内容变了，影响哪些角色、材料与验收？ | 由规则负责人确认；只改链接无法回答旧稿是否需要重做 |
| 作出决定 | 何时生效，哪些在办工作迁移，哪些仍按原约定完成？ | 由有权者决定并通知受影响者；不能仅凭“版本更新”自动改变已确认范围 |
| 切换使用 | 当前入口、任务说明、示例与检查依据是否一致？ | 维护者落实决定，使用者确认访问和理解；在办工作分别记录所用版本和决定依据 |
| 退出旧入口 | 旧副本是否仍会被当成当前说明？历史依据怎样保留？ | 标注旧版适用范围与替代入口，保留必要记录；不能删除历史后让已有交接失去依据 |

R3也是推演，不是原培训已经发生的变更。具体影响评估与批准接到[PM-09]({{< relref "project-management/project-management-09-change-control.md" >}})。如果新版本有问题，先由有权者确认临时办法及其适用范围；旧版已知错误时，不能把“回退”理解为无条件重新启用它。

例外要与永久改规则分开。例如，一次外部接收者没有页面访问权限，可能需要由负责人提供经确认的受控副本，并记录接收者、版本、用途和失效条件。这并不证明统一入口对所有人都无效，也不意味着今后可以随意散发副本。若同一例外不断发生，就应重新检查适用范围和访问安排。

为维护保留可安排的投入。除了试用后的复查，还可由规则变更、角色更换、重复异常和约定的最晚复查时间触发检查。是否每天、每周或每月复看，取决于变化速度和失效后果；本篇不给所有流程统一设一个频率。维护者离开时先移交责任和访问条件，没有接手者就明确当前支持限制。

## 六、分别看采用、帮助和代价

PM-22已经区分动作完成、实际采用和结果变化。持续维护时还要问：**换人或换一批任务后，做法是否仍能支持同一种结果？**

下面给出一组独立的模拟练习记录，不是原培训的试用结果。一个观察窗口内有四次事先判定适用的交接：

| 交接 | 观察到的使用过程 | 可以记录的结论 |
| --- | --- | --- |
| H1、H2 | 使用者从新入口取得已确认的本次版本，独立完成规定的交接记录 | 两次在本项观察中独立完成；不代表其他任务也会用 |
| H3 | 维护者代为取得版本并填写交接记录 | 本次交接用了新入口，但没有证明使用者能够独立使用 |
| H4 | 使用者沿旧消息取到副本，未核清适用版本 | 本次未完成新约定；还要查入口、访问和说明问题，不能只填“不配合” |

按这组题设，三次交接使用了新入口，占四次的3/4；独立完成规定交接的只有两次，占2/4。两项回答不同问题，分母都是这四次适用交接。没有发生适用任务时，应写“尚无观察机会”，不记成零采用或全部采用。

这些记录仍不能证明错误减少或交付加快。还需观察材料差异、检查范围与发现时点，同时记录维护者协助、更新和等待。记录口径接[PM-20]({{< relref "project-management/project-management-20-measurement-and-variance.md" >}})；数据量小、条件不同或其他变化未排除时，只报告相应观察，不宣称因果收益。

复查据此作出具体决定：H3提示检查哪些支持尚未交给使用者，H4提示追踪旧入口为什么仍在使用。若通过调整任务入口就能解决，就先改入口；若规则本身含糊，则交回规则负责人。不能一见未采用就新增审批，也不能一见有人用就扩大到全组织。

## 七、把修改与退出也做完

Berkun把能够修改或删除自身列为好流程的一项特征。[1] 退出的对象可能只是重复的记录步骤，也可能是整个做法；应说清哪些必要目标和保护仍由谁承担。

| 观察与条件 | 可考虑的决定 | 需要留下的后续安排 |
| --- | --- | --- |
| 目标问题仍存在，做法确被使用，代价可接受 | 在已核对的范围内继续 | 保留维护者、下一次复查和未覆盖条件 |
| 主要障碍是找不到入口、不会处理例外 | 修改并再观察 | 明确修改者、受影响用户和重新核对的任务 |
| 另一项机制已覆盖相同目的，旧步骤只增加重复劳动 | 比较后合并或停止旧步骤 | 核对替代机制的覆盖、失败处理和责任，不只看功能名称相似 |
| 原需求消失，或已有证据表明做法无关、代价过高 | 停止或换办法 | 有权者确认；安排在办任务、通知使用者、标注旧入口及保留必要历史 |
| 暂无维护者或有效输入，仍有必要任务 | 暂停受影响部分或安排受控替代 | 明确支持限制、临时负责人及恢复条件，不能把失管写成正常运行 |

一次没有出错不足以支持删除保护；沿用多年也不足以证明必须保留。要回到它原本保障的目标，检查替代方式和新风险，再由相应有权者作决定。

读者可以选一项正在使用的清单或约定，填出第三节的一页说明，再补答三个问题：下一位成员从哪里找到它？维护者明天不在时谁接手？什么证据会让团队缩小、修改或停止它？如果答案仍是“大家应该知道”，就先补使用与责任的断点，不急着再建一个系统。

技术交付场景可继续读[FDE交付方法]({{< relref "delivery-engineering/fde-02-delivery-method.md" >}})，把使用障碍接到现场记录、能力入口与原任务复验。本篇的通用说明可以作为维护底稿，不能替代某个项目的真实采用和收益材料。

## 来源与延伸阅读

1. Scott Berkun，《项目管理之美》，机械工业出版社，2009，ISBN 9787111259527，第10章“怎样才能不惹恼别人：流程、电子邮件和会议”，重点为“好流程的效果”“如何建立流程并付诸实践”。用于问题导向、替代方案、有限试用与修改退出；未采用书中简化收益公式，也不把忽视组织流程的个人经验作为建议。
2. Andrew S. Grove，《格鲁夫给经理人的第一课：畅销版》，中信出版社，2017，ISBN 9787508678092，第3章“管理杠杆率”中的“标准化”。用于共同做法与继续改进的关系，不引入固定管理人数或效果数字。
3. 同书第16章“别等火烧眉毛才培训”。用于工作需要、培训责任与新成员／新做法的学习安排；本文练习为自行设计，未声称执行了书中的培训方案。
4. 同书第10章“每个人都听命于三个‘长官’”。用于说明控制方式应与环境匹配；不据其人物举例给成员划分固定类型，不把文化认同当成额外投入或越权的授权。
