角色预算最容易被简化成：

- 主角多少面
- NPC 多少面

但真正能执行的角色预算表，必须把单体规格和同屏规模写在一起。

这张表先描述制作输入，再关联阶段观测和接受规则。空格表示待填写，不表示零成本或已经通过；面数、骨骼数、材质数量都不能单独换算为毫秒。

## 模板字段

| 字段 | 主角 | Boss | 精英 | 普通 NPC |
|------|------|------|------|---------|
| 面数 / 顶点数 |  |  |  |  |
| 材质球数量 |  |  |  |  |
| 骨骼数 |  |  |  |  |
| 蒙皮影响数 |  |  |  |  |
| 贴图套数 / 分辨率 |  |  |  |  |
| Shader 特性 |  |  |  |  |
| LOD 层级 |  |  |  |  |
| 同屏数量 |  |  |  |  |

面数/顶点数注明整个 Mesh 或子网格及 LOD，骨骼/影响数注明资产规格与实际使用范围；材质和贴图保留资源身份、实例副本、有效格式/Mip 与 Shader 特性。共享资源去重，主画面、阴影等用途分开；详细机制与阶段要求复用[角色预算的观测记录]({{< relref "performance/game-budget-08-character-budget.md#character-task-observation-record" >}})。

## 让规格表能回到规则和证据

同一份规格表可以被多个场景引用，每次验收应另绑定以下记录；共用内容可用 ID/版本引用，不必复制全文。

| 关联记录 | 至少填写什么 |
| --- | --- |
| 指标定义 | 指标 ID/版本、对象、单位、计数/起止范围、窗口/聚合及事件/帧关联；规格、工作输入、耗时和内存口径分别列 |
| 实际配置与组合 | 构建/内容、引擎/管线、设备/OS/API、实际画质/分辨率、LOD/Fade/阴影/Shader；任务/镜头、角色类型/外观/实例与 VFX/UI/场景背景 |
| 阶段与状态 | 创建、换装、远近稳定/过渡、同屏峰值或退出/复用；起止和必要反馈、缓存/池/持有、运行/请求代次，配置变化分段 |
| 来源与检查事实 | 拟用工具/版本、目标 Player 支持与扰动方案；有观测后填原始记录、有效性与缺失原因，业务结果另记；未采集不能填写实测通过 |
| 规则与处理决定 | 规则 ID/版本、制作预警或性能接受用途、阈值依据/校准状态及适用条件；符合/超线/证据不足、处理责任、复验或例外到期 |

规则依据、有效检查事实与接受决定分别保存，写法沿[预算规则记录]({{< relref "delivery-engineering/delivery-performance-stability-02-budget-system.md" >}})。同样叫“中档”不代表配置或负载相同；候选线、空白值或教学参数都不能补成已验证规则。表格填齐只提供验收输入，是否接受还需匹配规则的有效证据与必要表现检查。

## 为什么这张表比面数表更有用

因为角色真实成本来自：

- 几何
- 材质
- 动画和蒙皮
- 贴图
- Shader
- 同屏叠加

## 怎么用

1. 先按角色类型填单体规格。
2. 再按玩法填同屏数量。
3. 按目标设备与实际配置列候选版本，分别关联创建、换装、LOD 过渡和同屏组合等阶段记录。
4. 在适用规则下核对有效观测及必要表现，保留超线、缺失与处理决定。减少保留资源或降低 LOD/阴影时，也要复验驻留、再次准备、轮廓/装备识别、投影和过渡连续性。

## 最短结论

角色预算模板真正值钱的地方，是把：

`单体规格、同屏组合、实际配置与使用阶段的共同约束，以及对应指标、规则和证据`

写成一张大家都能拿来验收的表。
